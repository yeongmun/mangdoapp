# 현장 사진 체크리스트 설계 (2026-10-24)

> 상태: 1~4단계 구현 완료(2026-10-24). 진행 기록은 프로젝트 문서 `claude/프로젝트-허브-설계.md` §9, 확인은 `claude/확인-체크리스트.md` 9~12장. 구현하며 바뀐 점: 전차보고서는 앱 서버가 hwpx를 직접 읽음(웹은 .hwp 변환만), 다시 올리면 안 찍은 옛 항목은 삭제가 아니라 휴지통, 페이지 id에 회차 접두사, 부재명 수정은 웹에서.

요구사항 원문: Claude 프로젝트 "대농" `claude/업무-프로세스-요구사항.md`.

## 목적
현장(정기안전점검·정밀안전점검·정밀안전진단)에서 **빼먹는 사진 없이** 복귀한다.
전차보고서가 있으면 그 손상사진을 같은 자리에서 다시 찍고, 없으면 시설물별 필수 사진 목록대로 찍는다.

## 사용자가 정한 것
- 웹(daenong)에서 과업을 등록하면 앱 프로젝트 목록에 **자동으로** 뜬다. (10/7 "자동 생성 안 함" 결정을 뒤집음 — 정기점검은 망도가 없어도 사진 때문에 앱이 필요)
- **점검 종류**(정기안전점검 / 정밀안전점검 / 정밀안전진단)와 **시설물 종류**(교량 / 터널 / 옹벽 / …)는 **앱에서** 고른다.
- 과업 하나에 구조물 여러 개 → 앱 프로젝트 2단계(과업 → 구조물) 그대로. 구조물 추가는 앱·웹 둘 다.
- 필수 사진 목록은 시설물별로 사용자가 나중에 준다. 지금은 UI만, 목록은 서버 설정 파일로 교체 가능하게.
- 전차보고서는 **한글 파일**(.hwp/.hwpx)을 웹에서 업로드 → 사진 있는 부분만 앱에 보여줌 → 사진을 누르면 카메라 → 찍으면 체크·테두리색으로 표시.
- **필수 사진과 전차 사진은 다른 화면.** 전차 사진이 있으면 그것만 보고 찍어도 되고, 필수 사진 목록은 전차 사진이 없을 때 쓰거나 참고용.
- 찍은 사진 파일명 `시설물이름_부재이름_사진번호.jpg`. 서버 업로드 때 축소 저장(기존 손상 사진과 같은 규칙).

## 결정 (작성자 판단, 이유 포함)
1. **과업→앱 동기화는 웹이 밀어넣는다.** 웹이 과업을 저장할 때(과업구분이 정기·정밀일 때만) 앱 서버 `POST /api/projects`로 프로젝트를 만들고 `appProjectId`를 붙인다. 기존 "연결" 흐름·중계 라우트를 재사용한다. 웹에는 쓰기 가능한 앱 키 `MANGDO_WRITE_KEY`가 하나 더 필요. 앱 서버가 웹을 읽는 방식(pull)은 웹에 API·키를 새로 열어야 해서 뺐다.
2. **한글 파일 사진 추출은 서버(앱 서버 또는 웹)에서.** `.hwpx`는 zip → `BinData/` 그림과 본문 XML의 캡션(사진 번호·설명)을 뽑는다. `.hwp`는 사내 PC 한컴 COM으로 hwpx 변환 후 같은 길(daenong이 이미 한컴 COM을 쓴다). 앱은 결과(이미지+캡션)만 받는다. 캡션을 못 읽은 사진은 번호 칸을 비워 두고 사람이 적는다.
3. **데이터는 "촬영 항목(shot)" 하나로, 화면은 둘.** 구조물마다 `shots[]`: `{ id, kind: 'required' | 'previous', member, label, number, refImage?, photo?, takenAt? }`. 필수 사진 화면은 `required`만, 전차 사진 화면은 `previous`만 보여준다. 망도 손상 사진(`damages[].attrs.photoNumbers`)은 건드리지 않는다.
4. **오프라인 우선.** 항목 목록·전차 사진 썸네일은 과업을 받을 때 태블릿에 저장. 찍은 사진은 기존 업로드 큐(`photoQueue`)로 올린다.
5. **앱 프로젝트에 필드 2개 추가**: `inspectionType`(점검 종류), `facilityType`(시설물 종류). 둘 다 선택 사항(기존 프로젝트는 비어 있음). 시설물 종류는 구조물(하위) 단위, 점검 종류는 과업(상위) 단위.

## 화면(앱)
- 프로젝트 목록(기존). 과업(상위)을 열면 상단에 **점검 종류** 선택. 구조물(하위)을 열면 상단에 **시설물 종류** 선택. 한 번 고르면 저장.
- 구조물 화면 탭 3개: **[도면]**(기존) · **[필수 사진]** · **[전차 사진]**. 전차 사진이 하나라도 있으면 [전차 사진]을 기본 탭으로.
- [필수 사진]: 시설물 종류에 따른 목록을 부재별로 묶어 카드. 회색 테두리 = 안 찍음, 초록 테두리 + ✓ = 찍음. 상단 "12/20 찍음". 카드 탭 → 카메라 → 찍으면 즉시 표시. 다시 찍기 가능.
- [전차 사진]: 전차보고서에서 뽑은 사진을 썸네일 카드로(캡션·번호 함께). 같은 규칙으로 찍음 표시. 탭 → 카메라.
- 디자인은 `ui-ux-pro-max` 스킬로 이 화면부터 적용(React Native 스택).

## 화면(웹)
- 과업 저장 시 앱 프로젝트 자동 생성(정기·정밀만). 과업 상세의 [연결] 드롭다운은 남겨 둔다(이미 있는 앱 프로젝트에 붙일 때).
- 과업 상세: **전차보고서(한글) 업로드** → 추출된 사진 수 표시. **구조물 추가**. 찍은 사진 보기·내려받기(자료함).

## 서버(앱)
- `ProjectRecord` + `inspectionType?`, `facilityType?`.
- `server/data/shots/<projectId>.json` — 촬영 항목. 필수 목록 원본은 `server/config/requiredShots.json`(시설물 종류 → 부재 → 항목). 구조물에 시설물 종류를 고르면 그 목록으로 `required` 항목을 만든다(이미 있으면 유지).
- 전차 사진: `POST /api/projects/:id/previous-report`(hwpx/hwp) → 추출 → `previous` 항목 + 참조 이미지 파일.
- 찍은 사진: `POST /api/projects/:id/shots/:shotId/photo`(기존 `photoShrink` 규칙) → `<시설물이름>_<부재>_<번호>.jpg`.
- 사진 zip·사진첩 연계는 기존 `photos.zip`에 shot 사진을 합친다.

## 만드는 순서 (단계마다 실기기 확인 가능)
1. 앱 프로젝트에 점검 종류·시설물 종류 + 웹 과업 저장 → 앱 프로젝트 자동 생성·연결.
2. [필수 사진] 탭: 샘플 목록(교량 10항목) + 촬영·체크·업로드·파일명.
3. 웹 한글 파일 업로드 → 사진·캡션 추출 → [전차 사진] 탭.
4. 웹 과업 상세: 구조물 추가, 찍은 사진 보기.

## 하지 않는 것
비파괴 · 망도 신규 손상 그리기 변경 · 보고서 자동 작성 · 전차 손상과 망도 손상의 자동 매칭.

## 열린 것
- `.hwp`(구형)이 많으면 한컴 변환 시간 — 3단계에서 실측.
- 전차 사진 캡션이 표 밖에 있는 보고서는 번호를 못 읽을 수 있음 → 사람이 고치는 칸.
- 필수 사진 목록 실제 내용 — 사용자가 시설물별로 줄 때 `requiredShots.json`만 바꾼다.
