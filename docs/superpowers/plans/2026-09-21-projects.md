# 프로젝트 관리 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 도면을 프로젝트(최대 2단계 폴더)로 묶고, PC에서 관리하며, 앱에서 프로젝트를 골라 도면을 열고, 프로젝트 단위로 사진·산출 DXF를 zip으로 받는다.

**Architecture:** 서버에 `projects.json`과 `ProjectsStore`를 더하고 도면 레코드에 `projectId`만 붙인다(손상·사진·산출 형식 불변). 트리 계산(`ProjectView`)은 서버의 순수 함수가 해서 PC 페이지와 앱이 같은 결과를 받는다. 앱의 "무엇을 보여줄지"는 import 없는 순수 모듈 `src/projectList.ts`에 두어 서버 vitest가 검사한다.

**Tech Stack:** Node 24 · TypeScript(NodeNext, `.js` 접미사 import) · Express 5 · archiver 7 · vitest + supertest / 뷰어·PC 페이지는 plain ESM JS / 앱은 Expo SDK 57 · React Native · `expo-file-system`.

**Spec:** `docs/superpowers/specs/2026-09-21-projects-design.md` (binding — 계획과 어긋나면 스펙이 이긴다)

## Global Constraints

- 커밋 메시지는 한국어, 끝에 정확히 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- git: 파일은 **이름으로** 스테이징한다. `git add .` / `git add -A` / `git commit -a` / `git checkout` / `git restore` / `git stash` 금지.
- `.dxf` 픽스처와 `server/data/`는 절대 고치지 않는다. `.env`·`.env.local`은 커밋하지 않는다.
- `docs/DXF산출-테스트-결과.md`는 제자리에서 행만 덧붙인다(사용자 메모 보존).
- 서버 TS import는 `.js` 접미사. 뷰어·PC 페이지 JS는 의존성 없는 plain ESM.
- `src/projectList.ts`는 **아무것도 import하지 않는다**(서버 vitest가 상대 경로로 가져간다).
- 문구는 스펙의 표·본문에 적힌 것을 **글자 그대로** 쓴다.
- 손상 기록(schemaVersion 5), 사진 폴더 구조, 도면별 zip·산출, 휴지통 API의 동작을 바꾸지 않는다.

**Interfaces:**
- Produces (`projectsStore.ts`):
  ```ts
  export interface ProjectRecord { id: string; name: string; memo: string; parentId: string | null; createdAt: string }
  export type ProjectRuleCode = 'name' | 'memo' | 'parent' | 'depth' | 'duplicate' | 'notEmpty';
  export class ProjectRuleError extends Error { constructor(readonly code: ProjectRuleCode, message: string) }
  export function newProjectId(): string            // 'p_' + 32 hex
  export function isProjectId(value: unknown): boolean // /^p_[0-9a-f]{32}$/
  export const PROJECT_NAME_MAX = 80; export const PROJECT_MEMO_MAX = 500;
  export class ProjectsStore {
    constructor(filePath: string)
    list(): Promise<ProjectRecord[]>                 // 저장 순서 그대로
    get(id: string): Promise<ProjectRecord | null>
    create(input: { name: unknown; memo?: unknown; parentId?: unknown }, createdAt: string): Promise<ProjectRecord>
    update(id: string, patch: { name?: unknown; memo?: unknown }): Promise<ProjectRecord | null> // 없으면 null
    remove(id: string, usage: { drawingCount: number }): Promise<ProjectRecord | null>          // 없으면 null
  }
  ```
  - `create`: name은 문자열·trim 후 1~80자(아니면 `name`), memo는 없으면 `''`, 문자열·trim 후 ≤500(아니면 `memo`), parentId가 `null`/`undefined`/`''`면 최상위, 값이 있으면 그 프로젝트가 있어야 하고(`parent`) 그 프로젝트의 `parentId`가 null이어야 한다(`depth`), 같은 parentId에 같은 name이 있으면 `duplicate`.
  - `update`: 준 키만 바꾼다. name을 바꾸면 자기 자신을 뺀 형제와 `duplicate` 검사. `parentId`는 못 바꾼다.
  - `remove`: 하위 프로젝트 수 M(스토어가 센다)이나 `usage.drawingCount` N이 0보다 크면 `notEmpty`, 문구 `비어 있는 프로젝트만 삭제할 수 있습니다. 도면 N개, 하위 프로젝트 M개가 있습니다.`
  - 읽고-고치고-쓰기는 `DrawingsStore.serialize`와 같은 방식으로 한 줄로 세운다. 파일은 `readJsonFile`/`writeJsonFileAtomic`.
- Produces (`projectTree.ts`, 순수):
  ```ts
  export interface ProjectView extends ProjectRecord { depth: 0 | 1; path: string; drawingCount: number; totalDrawingCount: number; childCount: number }
  export const PATH_SEPARATOR = ' › ';
  export function effectiveProjectId(projectId: unknown, projects: ProjectRecord[]): string | null // 없거나 모르는 id면 null
  export function buildProjectViews(projects: ProjectRecord[], drawings: { projectId?: string | null }[]): ProjectView[]
  export function descendantIds(projectId: string, projects: ProjectRecord[]): string[] // 자기 자신 먼저, 이어서 하위(이름순)
  ```
  - 순서: 최상위 이름순(`a.name.localeCompare(b.name, 'ko')`), 각 최상위 바로 뒤에 하위 이름순. parentId가 가리키는 상위가 없는 레코드(파일 손상)는 최상위로 취급한다.
- Produces (`drawingsStore.ts`): `DrawingRecord.projectId?: string | null`, `DrawingPatch`에 `'projectId'` 추가.

  - `'unfiled'`: `projectId`가 없거나 목록에 없는 id인 도면.
  - 프로젝트 안: `parentId === location`인 프로젝트들, 이어서 `projectId === location`인 도면들.
