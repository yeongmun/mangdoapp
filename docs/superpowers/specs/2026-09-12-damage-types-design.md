- 근거: `docs/기능명세서.md` F-3(손상 입력), F-4(손상물량표), `docs/superpowers/specs/2026-09-10-phase1-poc-design.md`(1단계 PoC), 사용자 확인 사항(2026-09-12)

## 1. 목표와 범위

**목표**: 1단계에서 균열 1종만 입력하던 것을, 사내에서 실제로 쓰는 손상 유형 전체로 확장한다. 유형마다 입력 방식·표시·DWG 출력 규칙을 한 곳에 정의해 두고, 유형이나 해치가 바뀌어도 그 정의만 고치면 되게 한다.

**포함**
- 손상 유형 정의(10종)와 그 정의를 담는 파일
- 유형별 입력: 선형은 폴리라인, 면형은 회전 가능한 사각형
- 화면 표시: 테두리 + 유형별 무늬(해치 흉내)
- 물량: 길이·면적을 직접 입력. 도형에서 계산한 값은 참고 표시
- 저장 형식 v2와 기존 v1 문서 호환
- DWG 출력 규칙 정의 (실제 출력 구현은 2단계)

**제외**
- 손상물량표(Table 객체) 자동 작성 — 기능명세서 F-4.3, 이후 단계
- 사진 첨부, 프로젝트·사용자 관리 — 4단계
- 손상 유형별 세부 속성(폭·깊이 외 추가 항목) 확장

## 2. 손상 유형 (확정 10종)

레이어는 전부 `신규손상`, 색은 빨강으로 통일한다(사용자 확인).

| id | 이름 | 입력 | 채우기 | 물량 단위 |
|---|---|---|---|---|
| `crack` | 균열 | 선 | 없음 | m |
| `map_crack` | 망상균열 | 면 | 해치 `ANCHORLK` 축척 50 | ㎡ |
| `breakage` | 파손 | 면 | 해치 `ANSI33` 축척 50 (기타와 동일) | ㎡ |
| `segregation` | 재료분리 | 면 | 해치 `CORK` 축척 35 | ㎡ |
| `delamination` | 박리 | 면 | 해치 `ANSI31` 축척 50 | ㎡ |
| `spalling` | 박락 | 면 | 해치 `ANSI37` 축척 60 | ㎡ |
| `efflorescence` | 백태·열화 | 면 | 해치 `TRIANG` 축척 25 | ㎡ |
| `etc` | 기타 | 면 | 해치 `ANSI33` 축척 50 | ㎡ |
| `rebar_exposure` | 철근노출 | 면 | 기호 — 나란한 선 2개 + 양 끝 ✕ (4.1절) | ㎡ |
| `crack_efflorescence` | 균열/백태 | 선 | 기호 — 선 + 주위에 반복되는 원 (4.1절) | m |

- 사용자가 준 이름 `ANS131`, `AN137`, `ANS133`은 캐드 표준 이름 `ANSI31`, `ANSI37`, `ANSI33`으로 본다(사용자 확인).
- `ANCHORLK`는 오토캐드 기본 패턴에 없지만 **대체하지 않는다**. 사내 망도(`docs/exam.dxf`)에서 패턴 정의를 그대로 읽어냈고(부록 A), DXF·DWG의 해치는 패턴 정의를 엔티티 안에 담기 때문에 `.pat` 파일 없이도 똑같이 그려진다.
- 해치 축척값은 사내 망도에서 읽은 실제 값이다(2026-09-14). 저장된 간격이 `표준 패턴 간격 × 축척`과 정확히 맞아떨어져 교차 확인했다 — 예: ANSI31은 3.175mm × 50 = 158.75.
- 파손은 기타와 같은 `ANSI33`을 쓴다(사용자 확인 2026-09-14). 도면에서 파손과 기타는 무늬로 구분되지 않고 물량표의 이름으로만 구분된다 — 그렇게 하기로 정했다.
- **철근노출**과 **균열/백태**는 해치로 채우지 않는다(사용자 확인). 선과 원으로 이루어진 기호를 그리며, 모양과 치수는 4.1절에 있다. 입력 방식은 다른 유형과 같다(철근노출은 사각형, 균열/백태는 선).

## 3. 유형 정의 파일

`server/public/viewer/damageTypes.js` 하나에 모은다. 서버도 이 파일을 읽어 검증에 쓴다(1단계의 `damageDoc.js`와 같은 방식).

```js
{
  id: 'spalling',
  label: '박락',
  kind: 'area',                                   // 'line' | 'area'
  fill: { kind: 'hatch', pattern: 'ANSI37', scale: 1, angle: 0 },
  //    { kind: 'block', name: '…' } | null       // null이면 테두리만
  layer: '신규손상',
  colorIndex: 1,                                  // 캐드 색 번호 1 = 빨강
  quantityUnit: 'm2',                             // 'm' | 'm2'
  // 선·원 도형 유형(철근노출, 균열/백태)에만 쓰는 값. 도면 실제 치수 기준 고정값이다.
  decoration: { kind: 'circles', diameterMm: null, spacingMm: null },
}
```

- 앱·뷰어·서버가 모두 이 목록을 기준으로 동작한다. 유형 추가는 이 배열에 한 줄 추가하는 것으로 끝난다.
- 해치 축척(`scale`)의 실제 값은 아직 확인되지 않았다. 기본 1로 두고 도면을 보며 맞춘다.

## 4. 입력 방식

**선형(균열)**: 1단계 그대로. 펜으로 긋고 약한 단순화를 적용한 폴리라인.

**면형(나머지 9종)**: 회전 가능한 사각형.
1. 유형을 고르고 도면 위를 드래그하면, 시작점과 끝점을 대각선으로 하는 **가로·세로 방향 사각형**이 만들어진다.
2. 사각형을 탭해 선택하면 네 모서리에 크기 조절 핸들, 위쪽에 **회전 핸들**이 나타난다. 회전 핸들을 끌면 사각형 중심을 기준으로 돌아간다.
3. 회전 각도는 도면 좌표계 기준으로 저장한다. 화면을 회전해도 값은 변하지 않는다.

**선택한 손상 이동 (2026-09-14 추가)**: 선택한 손상의 몸통 — 사각형은 안쪽, 선은 선 위 — 을 끌면 그대로 옮겨진다. 처음에 잘못된 자리에 그렸을 때 미세하게 옮기는 용도다(사용자 요청).
- 선택하지 않은 상태에서 끌면 지금처럼 새 손상을 그린다. 그래야 그리기와 이동이 헷갈리지 않는다.
- 사각형에서는 모서리·회전 핸들이 이동보다 우선이다.
- 손을 떼면 저장된다. 두 손가락 핀치, 펜 가로채기, `pointercancel`, 속성 패널 열림으로 취소되면 원래 자리로 돌아간다(크기·회전 조절과 같은 규칙).
- 옮긴 뒤에도 선택은 유지된다. 이어서 핸들로 조절할 수 있어야 한다.
- 이동량이 0이면(탭만 하고 뗌) 저장하지 않는다.
- 사용자가 입력한 물량(`measured`)은 건드리지 않고, 도형에서 계산한 참고값(`computed`)만 새 위치로 다시 계산한다.
- 옮기면 번호가 바뀔 수 있다. 번호는 저장하지 않고 위치에서 계산하므로 맞는 동작이다.

**선·원 기호 유형(철근노출, 균열/백태)**: 입력 방식은 다른 유형과 같다(사용자 확인 2026-09-14). 철근노출은 사각형으로 그리고 물량은 ㎡, 균열/백태는 선으로 긋고 물량은 m이다. 달라지는 것은 **그 위에 그리는 기호**뿐이다. 모양과 치수는 아래 4.1절에 있다.

### 4.1 선·원 기호의 모양과 치수

`docs/exam.dxf`(사용자 제공 사내 망도, 2026-09-14)의 범례를 실측한 값이다. **모두 도면 단위(mm)이며 실물 크기 기준이다.**

**철근노출** — 나란한 가로선 2개, 양 끝에 ✕ 하나씩

| 항목 | 값(mm) |
|---|---|
| 전체 길이 | 1221 |
| 두 선 사이 간격 | 57.4 |
| ✕ 하나의 크기 | 212 × 212 |
| ✕ 중심 사이 거리 | 1009 |

그리는 규칙: 사각형의 긴 변 방향을 따라 가운데에 선 2개를 긋고, 양 끝에 ✕를 둔다. 선 간격(57.4)과 ✕ 크기(212)는 고정값이고, 선 길이만 사각형 크기에 맞춘다.

**균열/백태** — 그은 선 + 선 주위의 작은 원

| 항목 | 값(mm) |
|---|---|
| 원 지름 | 54.4 |
| 선에서 원 중심까지 | 77 (위) / 87~91 (아래) |
| 원 사이 간격 | 약 158 |

그리는 규칙: 그은 선을 따라 **일정 간격(158)으로 원을 반복**하고 위·아래를 번갈아 둔다(사용자 확인 2026-09-14). 범례의 원 5개는 짧은 예시일 뿐이며, 긴 균열에는 그만큼 많이 찍힌다.

**축척 환산이 필요 없는 이유**: 사내 망도는 구조물을 실물 크기 그대로 mm로 그린다. `docs/exam.dxf`의 손상 해치 영역이 10.7m × 0.9m, 16.4m × 3.8m처럼 실제 부재 크기로 찍혀 있는 것이 근거다. 따라서 기호 치수와 해치 축척은 도면이 바뀌어도 같은 값을 쓴다. 다만 도면이 mm가 아닌 단위로 그려져 있으면(예: m 단위) 기호가 1000배로 나오므로, 1단계에서 이미 구하는 페이지→모델 변환으로 단위를 확인해 환산한다.

기울어진 부재에 맞춰 그려야 한다는 사용자 확인에 따라 회전을 넣는다. 자유 폐합 윤곽 입력은 넣지 않는다. 물량을 직접 입력하므로 도형은 위치·범위 표시용이고, 사내에서도 사각형으로 그려 왔다.

## 5. 화면 표시

- 테두리: 빨간색, 화면 기준 1px (선택 시 주황 2px) — 1단계와 동일
- 채우기: 유형별 무늬를 SVG 패턴으로 그린다. 무늬 간격은 **도면 실치수 기준**이라 확대·축소하면 함께 커지고 작아진다(2026-09-14 사용자 확인으로 변경. 그 전에는 화면 기준 고정이었다). 간격은 2장의 유형별 해치 축척을 그대로 쓴다 — 예를 들어 박리(ANSI31 축척 50)는 도면상 158.75mm 간격이다. 선 굵기와 글자 크기도 같은 기준을 따르므로, 화면에서 보는 모습이 산출 DWG와 같아진다.
- 도면 좌표 변환을 구하지 못한 도면에서는 기준 삼을 실치수가 없으므로 예전처럼 화면 기준 고정 크기로 그린다.
- 선택했을 때 나오는 크기·회전 핸들은 **화면 기준 고정**으로 둔다. 손으로 잡는 조작용이라 배율에 따라 커지거나 작아지면 쓰기 어렵다.
  - `ANSI31`: 45° 빗금 / `ANSI33`: 45° 이중 빗금 / `ANSI37`: 교차 빗금 / `ANCHORLK`: 마름모 격자 / `TRIANG`: 삼각형 / `CORK`: 사선 + 점 (임시로 쓰던 `NET`은 2026-09-15 제거)
  - 화면용 근사 표현이며, 산출 DWG에서는 진짜 해치 패턴이 들어간다.
- 채우기가 미정인 유형: 테두리만 그리고 사각형 안쪽에 유형 이름을 작게 표시한다.

## 6. 물량

- 물량표에 들어가는 값은 **사용자가 직접 입력한 값**이다(사용자 확인: 길이·면적 모두 수기 측정).
- 앱이 도형에서 계산한 값은 같은 입력창에 "참고: 12.4 m" 처럼 회색으로 보여준다. 입력을 비워 두면 물량은 비어 있는 것으로 본다.
- 손상을 선택하면 속성 입력창이 열린다: 길이(m) 또는 면적(㎡), 폭(mm, 균열류), 부재명, 비고.
- 참고값의 단위 환산은 도면 단위가 확정돼야 한다(9장 미확정 항목).

## 7. 저장 형식 (schemaVersion 2)

```json
{
  "schemaVersion": 2,
  "drawingId": "d_…",
  "updatedAt": "2026-09-12T…Z",
  "damages": [
    {
      "id": "uuid",
      "type": "spalling",
      "createdAt": "2026-09-12T…Z",
      "geometry": {
        "kind": "rect",
        "world": [[x, y], [x, y], [x, y], [x, y]],
        "dwg": [[x, y], [x, y], [x, y], [x, y]]
      },
      "measured": { "lengthM": null, "areaM2": 1.8 },
      "computed": { "lengthDwg": null, "areaDwg": 1800000 },
      "attrs": { "widthMm": null, "member": "거더 하부", "note": "" }
    }
  ]
}
```

- `geometry.kind`: `polyline`(선형) | `rect`(면형). 회전 사각형은 **네 꼭짓점**으로 저장한다. 각도를 따로 저장하지 않으므로 DWG 출력과 면적 계산이 단순해진다.
- `measured`: 사용자가 입력한 값. `computed`: 앱이 도형에서 계산한 참고값(DWG 좌표 단위).
- `dwg`가 `null`인 경우 처리는 1단계와 같다.
- **v1 호환**: 기존 문서를 읽을 때 `schemaVersion: 1`이면 각 손상을 `type: 'crack'`, `geometry.kind: 'polyline'`, `measured: { lengthM: null }`, `computed.lengthDwg = 기존 lengthDwg`로 변환해 읽는다. 저장할 때는 v2로 쓴다.

## 8. DWG 출력 규칙 (2단계에서 사용)

모든 손상 엔티티는 레이어 `신규손상`, 색 번호 1(빨강)로 만든다.

| 입력 | 출력 |
|---|---|
| 선형 | `LWPOLYLINE` (열린 폴리라인) |
| 면형 + 해치 | 닫힌 `LWPOLYLINE` + `HATCH`(패턴 이름·축척·각도, 비연관) |
| 면형 + 블록 | 닫힌 `LWPOLYLINE` + 블록 `INSERT` (블록 모양 확정 후) |
| 면형 + 채우기 없음 | 닫힌 `LWPOLYLINE` |

- 해치는 비연관으로 만든다. 지스타캐드에서 경계선을 지워도 무늬가 남고, 왕복 호환성이 높다.
- 사내 커스텀 패턴을 쓰게 되면 `.pat` 파일을 Design Automation 실행 환경에 함께 넣어야 한다.

## 9. 미확정 항목

**해결됨 (2026-09-14, 사용자 확인과 `docs/exam.dxf` 실측)**

1. 파손의 해치 → 기타와 같은 `ANSI33`. 도면에서 둘은 구분되지 않고 물량표 이름으로만 구분된다
2. 철근노출·균열/백태의 모양과 치수 → 4.1절
3. 원의 지름·간격 → 4.1절. 원은 길이와 무관하게 일정 간격으로 반복한다
4. 도면 단위 → **mm**. exam.dxf의 글자 높이 300과 범례 상자 3196×775는 mm로만 말이 된다. 도면의 단위 설정값은 `인치`로 되어 있지만 캐드 기본값이 그대로 남은 것이다

5. `ANCHORLK` → 대체하지 않고 원본 정의를 그대로 쓴다(부록 A)
6. 해치 축척 → 2장 표에 유형별로 적었다. 사내 망도에서 읽은 값이다

**남은 것**
