## 1. 목표와 범위

**목표**: 1단계에서 균열 1종만 입력하던 것을, 사내에서 실제로 쓰는 손상 유형 전체로 확장한다. 유형마다 입력 방식·표시·DWG 출력 규칙을 한 곳에 정의해 두고, 유형이나 해치가 바뀌어도 그 정의만 고치면 되게 한다.

**포함**
- 손상 유형 정의(10종)와 그 정의를 담는 파일
- 유형별 입력: 선형은 폴리라인, 면형은 회전 가능한 사각형
- 화면 표시: 테두리 + 유형별 무늬(해치 흉내)
- 물량: 길이·면적을 직접 입력. 도형에서 계산한 값은 참고 표시
- 저장 형식 v2와 기존 v1 문서 호환
- DWG 출력 규칙 정의 (실제 출력 구현은 2단계)

**제외**
- 손상물량표(Table 객체) 자동 작성 — 기능명세서 F-4.3, 이후 단계
- 사진 첨부, 프로젝트·사용자 관리 — 4단계
- 손상 유형별 세부 속성(폭·깊이 외 추가 항목) 확장

## 2. 손상 유형 (확정 10종)

레이어는 전부 `신규손상`, 색은 빨강으로 통일한다(사용자 확인).

| id | 이름 | 입력 | 채우기 | 물량 단위 |
|---|---|---|---|---|
| `crack` | 균열 | 선 | 없음 | m |
| `map_crack` | 망상균열 | 면 | 해치 `NET` (임시, 원래 `ANCHORLK`) | ㎡ |
| `breakage` | 파손 | 면 | **미정** (테두리만) | ㎡ |
| `segregation` | 재료분리 | 면 | 해치 `CORK` | ㎡ |
| `delamination` | 박리 | 면 | 해치 `ANSI31` | ㎡ |
| `spalling` | 박락 | 면 | 해치 `ANSI37` | ㎡ |
| `efflorescence` | 백태·열화 | 면 | 해치 `TRIANG` | ㎡ |
| `etc` | 기타 | 면 | 해치 `ANSI33` | ㎡ |
| `rebar_exposure` | 철근노출 | **선·원 도형** (입력 방식 확정 중) | 해치 아님 | ㎡ |
| `crack_efflorescence` | 균열/백태 | **선 + 선 주위의 원** (입력 방식 확정 중) | 해치 아님 | m |

- 사용자가 준 이름 `ANS131`, `AN137`, `ANS133`은 캐드 표준 이름 `ANSI31`, `ANSI37`, `ANSI33`으로 본다(사용자 확인).
- `ANCHORLK`는 캐드 기본 패턴에 없어 격자형 표준 패턴 `NET`으로 대체한다(사용자 확인). 실제 도면과 비교해 바꿀 수 있다.
- 채우기가 미정인 파손은 테두리만 그리고, 유형 목록에는 지금부터 넣는다. 정해지면 정의 파일 한 줄만 고친다.
- **철근노출**과 **균열/백태**는 해치로 채우지 않는다(사용자 확인). 선과 원으로 이루어진 도형이며, 균열/백태는 선형이라 물량 단위가 m이다. 두 유형의 입력 방식은 4장에서 확정한다.

## 3. 유형 정의 파일

`server/public/viewer/damageTypes.js` 하나에 모은다. 서버도 이 파일을 읽어 검증에 쓴다(1단계의 `damageDoc.js`와 같은 방식).

```js
{
  id: 'spalling',
  label: '박락',
  kind: 'area',                                   // 'line' | 'area'
  fill: { kind: 'hatch', pattern: 'ANSI37', scale: 1, angle: 0 },
  //    { kind: 'block', name: '…' } | null       // null이면 테두리만
  layer: '신규손상',
  colorIndex: 1,                                  // 캐드 색 번호 1 = 빨강
  quantityUnit: 'm2',                             // 'm' | 'm2'
  // 선·원 도형 유형(철근노출, 균열/백태)에만 쓰는 값. 도면 실제 치수 기준 고정값이다.
  decoration: { kind: 'circles', diameterMm: null, spacingMm: null },
}
```

- 앱·뷰어·서버가 모두 이 목록을 기준으로 동작한다. 유형 추가는 이 배열에 한 줄 추가하는 것으로 끝난다.
- 해치 축척(`scale`)의 실제 값은 아직 확인되지 않았다. 기본 1로 두고 도면을 보며 맞춘다.

## 4. 입력 방식

**선형(균열)**: 1단계 그대로. 펜으로 긋고 약한 단순화를 적용한 폴리라인.

**면형(나머지 9종)**: 회전 가능한 사각형.
1. 유형을 고르고 도면 위를 드래그하면, 시작점과 끝점을 대각선으로 하는 **가로·세로 방향 사각형**이 만들어진다.
2. 사각형을 탭해 선택하면 네 모서리에 크기 조절 핸들, 위쪽에 **회전 핸들**이 나타난다. 회전 핸들을 끌면 사각형 중심을 기준으로 돌아간다.
3. 회전 각도는 도면 좌표계 기준으로 저장한다. 화면을 회전해도 값은 변하지 않는다.

**선·원 도형 유형(철근노출, 균열/백태)**: 모양을 아직 받지 못했으므로 입력 방식은 나중에 확정한다(사용자 확인). 그때까지의 임시 동작은 다음과 같다. 목록에서 고를 수 있고 저장·물량 입력도 정상 동작하므로, 모양이 정해지면 그리는 부분만 바뀐다.

- `crack_efflorescence`(균열/백태, m): 균열과 같이 **선만** 긋는다. 선 주위의 원은 모양을 받은 뒤 추가한다.
- `rebar_exposure`(철근노출, ㎡): 면형과 같이 **사각형 테두리만** 그린다. 안쪽 선·원 도형은 모양을 받은 뒤 추가한다.

원의 크기와 간격은 **도면 좌표 기준 고정값**으로 한다(사용자 확인). 예를 들어 지름 200mm, 간격 500mm처럼 유형 정의에 실제 치수로 적는다. 화면을 확대하면 원도 함께 커지므로 산출 DWG와 모양이 같다. 실제 값은 모양을 받은 뒤 정한다.

기울어진 부재에 맞춰 그려야 한다는 사용자 확인에 따라 회전을 넣는다. 자유 폐합 윤곽 입력은 넣지 않는다. 물량을 직접 입력하므로 도형은 위치·범위 표시용이고, 사내에서도 사각형으로 그려 왔다.

## 5. 화면 표시

- 테두리: 빨간색, 화면 기준 1px (선택 시 주황 2px) — 1단계와 동일
- 채우기: 유형별 무늬를 SVG 패턴으로 그린다. 무늬 간격은 **화면 기준 고정**이라 확대해도 촘촘해지지 않는다. 캐드 해치의 느낌과 맞춘다.
  - `ANSI31`: 45° 빗금 / `ANSI33`: 45° 이중 빗금 / `ANSI37`: 교차 빗금 / `NET`: 격자 / `TRIANG`: 삼각형 / `CORK`: 사선 + 점
  - 화면용 근사 표현이며, 산출 DWG에서는 진짜 해치 패턴이 들어간다.
- 채우기가 미정인 유형: 테두리만 그리고 사각형 안쪽에 유형 이름을 작게 표시한다.

## 6. 물량

- 물량표에 들어가는 값은 **사용자가 직접 입력한 값**이다(사용자 확인: 길이·면적 모두 수기 측정).
- 앱이 도형에서 계산한 값은 같은 입력창에 "참고: 12.4 m" 처럼 회색으로 보여준다. 입력을 비워 두면 물량은 비어 있는 것으로 본다.
- 손상을 선택하면 속성 입력창이 열린다: 길이(m) 또는 면적(㎡), 폭(mm, 균열류), 부재명, 비고.
- 참고값의 단위 환산은 도면 단위가 확정돼야 한다(9장 미확정 항목).

## 7. 저장 형식 (schemaVersion 2)

```json
{
  "schemaVersion": 2,
  "drawingId": "d_…",
  "updatedAt": "2026-09-12T…Z",
  "damages": [
    {
      "id": "uuid",
      "type": "spalling",
      "createdAt": "2026-09-12T…Z",
      "geometry": {
        "kind": "rect",
        "world": [[x, y], [x, y], [x, y], [x, y]],
        "dwg": [[x, y], [x, y], [x, y], [x, y]]
      },
      "measured": { "lengthM": null, "areaM2": 1.8 },
      "computed": { "lengthDwg": null, "areaDwg": 1800000 },
      "attrs": { "widthMm": null, "member": "거더 하부", "note": "" }
    }
  ]
}
```

- `geometry.kind`: `polyline`(선형) | `rect`(면형). 회전 사각형은 **네 꼭짓점**으로 저장한다. 각도를 따로 저장하지 않으므로 DWG 출력과 면적 계산이 단순해진다.
- `measured`: 사용자가 입력한 값. `computed`: 앱이 도형에서 계산한 참고값(DWG 좌표 단위).
- `dwg`가 `null`인 경우 처리는 1단계와 같다.
- **v1 호환**: 기존 문서를 읽을 때 `schemaVersion: 1`이면 각 손상을 `type: 'crack'`, `geometry.kind: 'polyline'`, `measured: { lengthM: null }`, `computed.lengthDwg = 기존 lengthDwg`로 변환해 읽는다. 저장할 때는 v2로 쓴다.

## 8. DWG 출력 규칙 (2단계에서 사용)

모든 손상 엔티티는 레이어 `신규손상`, 색 번호 1(빨강)로 만든다.

| 입력 | 출력 |
|---|---|
| 선형 | `LWPOLYLINE` (열린 폴리라인) |
| 면형 + 해치 | 닫힌 `LWPOLYLINE` + `HATCH`(패턴 이름·축척·각도, 비연관) |
| 면형 + 블록 | 닫힌 `LWPOLYLINE` + 블록 `INSERT` (블록 모양 확정 후) |
| 면형 + 채우기 없음 | 닫힌 `LWPOLYLINE` |

- 해치는 비연관으로 만든다. 지스타캐드에서 경계선을 지워도 무늬가 남고, 왕복 호환성이 높다.
- 사내 커스텀 패턴을 쓰게 되면 `.pat` 파일을 Design Automation 실행 환경에 함께 넣어야 한다.

## 9. 미확정 항목

1. 파손의 해치 패턴 이름 (사용자가 확인 후 전달)
2. `ANCHORLK`를 대체할 최종 패턴 (지금은 `NET`)
3. 철근노출, 균열/백태의 선·원 모양과 그에 따른 입력 방식 (사용자가 나중에 제공). 그때까지는 4장의 임시 동작(선만 / 사각형 테두리만)으로 쓴다
4. 원의 지름·간격 실제 값 (도면 기준 mm). 기준은 정해졌고 숫자만 남았다
5. 해치 축척 값 — 도면을 보며 유형별로 맞춘다
6. 도면 단위(mm 추정) — 참고 물량값 환산에 필요. 1단계 스펙 §10에도 남아 있는 항목

## 10. 테스트 방침

- 단위 테스트: 유형 정의 목록의 무결성(중복 id, 필수 항목), v1 → v2 변환, 회전 사각형의 면적·꼭짓점 계산, 저장 문서 검증 규칙
- 수동 확인: 유형별로 그려서 화면 무늬가 구분되는지, 회전 핸들로 기울여지는지, 속성 입력값이 저장되는지, 기존 v1 문서를 열었을 때 균열이 그대로 보이는지
