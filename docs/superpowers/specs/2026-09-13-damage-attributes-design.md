# 손상 속성·물량 설계

- 날짜: 2026-09-13
- 앞선 설계: `2026-09-12-damage-types-design.md` (손상 유형 10종, v2 저장 형식)
- 이 문서가 v2의 6장(물량)과 7장(저장 형식)을 대체한다. 유형표·입력 방식·표시는 앞 문서가 그대로 유효하다.

## 1. 배경

v2에서는 사용자가 길이(m) 또는 면적(㎡)을 하나씩 직접 적었다. 실제 조사에서는 그렇게 적지 않는다.
가로·세로·개소를 적고 물량은 거기서 계산하며, 손상현황 이름과 번호도 규칙대로 붙는다.
현장 DWG의 표기(`(17) 0.2/1.5`)가 그 방식이다.

또한 2단계에서 물량표(Table 객체)를 자동 작성하려면 표의 각 칸이 계산 규칙을 가져야 한다.
이 설계는 그 규칙을 확정한다.

## 2. 사용자가 입력하는 것

속성 패널의 입력 칸은 네 개다.

| 칸 | 균열·균열/백태 | 나머지 여덟 유형 | 비고 |
|---|---|---|---|
| 가로/폭 | mm | m | 0 이상 또는 빈 값 |
| 세로/길이 | m | m | 0 이상 또는 빈 값 |
| 개소 | 개 | 개 | 0 이상의 정수 또는 빈 값 |
| 비고 | 자유 문자열 | 자유 문자열 | 빈 문자열 허용 |

`기타` 유형에만 **손상현황** 입력 칸이 하나 더 붙는다(자유 문자열).

빈 값은 "아직 측정하지 않음"이며 `null`로 저장한다. 0과 구분한다.

가로/폭의 단위가 유형에 따라 다른 이유는 균열 폭이 mm 단위로 관리되고 0.3mm/0.5mm 경계로
손상현황이 갈리기 때문이다. 화면에는 항상 단위를 함께 보여준다(`가로/폭 (mm)` / `가로/폭 (m)`).

## 3. 자동으로 정해지는 것

네 가지는 입력받지 않고 계산한다. **저장하지 않는다** — 저장하면 손상을 하나 지울 때마다
뒷번호를 전부 다시 써야 하고, 값과 위치가 어긋날 수 있다. 필요할 때마다 같은 함수로 계산한다.

### 3.1 번호

도면 위 위치로 정한다. 좌표는 `geometry.world`를 쓴다(모든 손상이 항상 갖고 있고, 같은 좌표계다).

1. 손상마다 경계상자의 중심과 높이를 구한다.
2. 중심 Y가 큰 것(도면 위쪽)부터 줄을 만든다.
3. 줄의 기준 Y에서 **허용 폭** 안에 드는 손상은 같은 줄로 본다.
4. 한 줄 안에서는 중심 X가 작은 것(왼쪽)이 앞번호다.
5. 줄이 끝나면 다음 줄 왼쪽으로 내려가 이어서 매긴다.
6. 번호는 1부터 시작하는 연속된 정수다.

**허용 폭**은 전체 손상 높이의 중앙값으로 한다. 도면마다 손상 크기가 달라 고정값을 쓰면
어떤 도면에서는 전부 한 줄이 되고 어떤 도면에서는 전부 따로 놀게 된다. 손상이 없거나
중앙값이 0이면 허용 폭을 0으로 두고 Y가 정확히 같을 때만 같은 줄로 본다.

동점 처리: 같은 줄에서 X가 같으면 Y가 큰 것이 앞, 그것도 같으면 `id` 오름차순으로 정한다.
같은 손상 집합이면 항상 같은 번호가 나와야 한다.

### 3.2 손상현황

| 유형 | 손상현황 |
|---|---|
| 균열 | 폭 < 0.3 → `균열(0.3mm미만)` / 0.3 ≤ 폭 < 0.5 → `균열(0.3mm이상)` / 0.5 ≤ 폭 → `균열(0.5mm이상)` |
| 균열/백태 | 같은 경계로 `균열/백태(0.3mm미만)` · `균열/백태(0.3mm이상)` · `균열/백태(0.5mm이상)` |
| 기타 | 사용자가 적은 손상현황. 비어 있으면 `기타` |
| 나머지 일곱 | 유형 이름 그대로 (`망상균열`, `재료분리`, `박리`, `박락`, `백태,열화`, `파손`, `철근노출`) |

균열류인데 폭이 비어 있으면 구간을 붙이지 않고 유형 이름 그대로 쓴다(`균열`, `균열/백태`).

### 3.3 물량(면적)

유형의 물량 단위에 따라 계산한다.

- 단위가 `m`인 유형(균열, 균열/백태): **세로/길이 × 개소**
- 단위가 `㎡`인 유형(나머지 여덟): **가로/폭 × 세로/길이 × 개소**

계산에 필요한 값 중 하나라도 비어 있으면 물량도 비어 있다(`null`). 0은 유효한 값이다.

균열류의 가로/폭은 mm이고 물량 계산에 쓰이지 않는다. 손상현황 구간을 정하는 데만 쓴다.

### 3.4 단위

유형표의 `quantityUnit`을 그대로 쓴다(`m` 또는 `㎡`). 사용자가 바꾸지 않는다.

## 4. 저장 형식 (schemaVersion 3)

```json
{
  "schemaVersion": 3,
  "drawingId": "...",
  "updatedAt": "2026-09-13T01:23:45.000Z",
  "damages": [
    {
      "id": "...",
      "type": "crack",
      "createdAt": "2026-09-13T01:23:45.000Z",
      "geometry": { "kind": "polyline", "world": [[..]], "dwg": [[..]] },
      "measured": { "width": 0.2, "length": 1.5, "count": 1 },
      "computed": { "lengthDwg": 4098.47, "areaDwg": null },
      "attrs": { "note": "", "statusText": "" }
    }
  ]
}
```

- `measured.width` / `measured.length` / `measured.count`: 0 이상의 숫자 또는 `null`. `count`는 정수.
- `computed`: v2와 같다. 도면에서 계산한 참고값이며 물량표에는 쓰지 않는다.
- `attrs.note`: 비고. 문자열.
- `attrs.statusText`: `기타` 유형의 손상현황. 다른 유형에서는 빈 문자열이어야 한다.
- v2의 `measured.lengthM` / `measured.areaM2` / `attrs.widthMm` / `attrs.member`는 없어진다.

`member`(부재명)는 쓰이지 않아 없앤다. 필요해지면 그때 다시 넣는다.

### 4.1 v2 → v3 변환

| v2 | v3 |
|---|---|
| `attrs.widthMm` | `measured.width` (균열류는 mm 그대로, 면형 유형은 값이 없었으므로 `null`) |
| `measured.lengthM` | `measured.length` |
| `measured.areaM2` (값이 있을 때) | `measured` 는 모두 `null`, 비고 앞에 `이전 면적 입력값: 1.8㎡` 를 붙인다 |
| `attrs.member` (값이 있을 때) | 비고 앞에 `부재명: 기둥` 을 붙인다 |
| `attrs.note` | `attrs.note` |
| 없음 | `attrs.statusText` = `""` |
| 없음 | `measured.count` = `null` |

면적에서 가로와 세로를 되돌릴 수 없으므로 지어내지 않는다. 값을 조용히 버리지도 않는다.
사용자가 비고에서 보고 다시 입력할 수 있게 옮겨 적는다. 비고가 이미 있으면 줄바꿈으로 잇는다.

### 4.2 v1 → v3 변환

v1 → v2 변환(앞 설계 7장)을 먼저 적용한 뒤 v2 → v3를 적용한다. 변환 단계를 이어 붙여
새 단계가 생겨도 각 단계를 따로 검증할 수 있게 한다.

## 5. 화면

### 5.1 속성 패널

```
[유형이름] 속성
번호 17 · 손상현황 균열(0.3mm미만) · 물량 1.5 m
가로/폭 (mm) [     ]
세로/길이 (m) [     ]
개소        [     ]
비고        [     ]
(기타일 때만) 손상현황 [     ]
[저장] [닫기]
```

- 맨 윗줄의 번호·손상현황·물량은 읽기 전용이며 입력에 따라 즉시 갱신된다.
- 값이 부족해 물량을 계산할 수 없으면 물량 자리에 `-` 를 보여준다.
- 0 이상이 아닌 값을 넣고 저장하면 v2와 같이 패널을 열어둔 채 알린다.
- 개소에 정수가 아닌 값을 넣으면 같은 방식으로 거부한다.

### 5.2 도면 위 표시

손상 옆 라벨은 **두 줄**이다(2026-09-14 사용자 확인, 사내 망도 표기에 맞춤).

```
   ⑰ 균열/백태          ⑰ 망상균열
    0.2/0.8              1.2x1.2
```

- 첫 줄: **원 안에 번호** + 손상 이름
- 둘째 줄: 물량 단위가 `m`인 유형은 `가로/세로`, `㎡`인 유형은 `가로x세로`
- 개소가 2 이상이면 뒤에 ` 2EA`를 붙인다
- 가로나 세로가 비어 있으면 둘째 줄을 그리지 않는다

첫 줄의 이름에는 **폭 구간을 붙이지 않는다**(`균열(0.3mm미만)`이 아니라 `균열`). 바로 아래 줄에 폭이 숫자로 나오므로 같은 정보가 두 번 들어가고 줄만 길어진다. 구간이 붙은 이름(`손상현황`)은 물량표에서 계속 쓴다. `기타`는 사용자가 적은 손상현황을 이름으로 쓴다.

문구를 만드는 함수는 `quantities.js`의 `drawingNameOf`(첫 줄 이름)와 `dimensionTextOf`(둘째 줄)이다. 물량표도 같은 함수를 쓴다.

라벨 위치는 도형 경계상자의 위쪽 가운데에서 화면 기준으로 조금 위(overlay.js의
`LABEL_OFFSET_PX`)다. 이 문단은 `2026-09-12-damage-types-design.md`가 라벨 위치에 대해 적은
문구("채우기가 미정인 유형: 테두리만 그리고 사각형 안쪽에 유형 이름을 작게 표시한다")를
**명시적으로 대체한다** — 그 문서의 나머지 내용(유형표·입력 방식·해치 등)은 그대로 유효하다.

## 6. 검증

`validateDamageDoc`은 v3 기준으로 바꾼다.

- `schemaVersion`이 3이어야 한다.
- `measured.width` / `length`: 0 이상의 유한한 숫자 또는 `null`.
- `measured.count`: 0 이상의 정수 또는 `null`.
- `attrs.note`: 문자열. `attrs.statusText`: 문자열이고, `기타`가 아닌 유형에서는 빈 문자열.
- 나머지(id, createdAt, type, geometry, computed)는 v2와 같다.

v2에 있던 "선형에서 areaM2는 null" 류의 규칙은 해당 항목이 없어져 함께 사라진다.

## 7. 2단계와의 연결

물량표의 각 행은 `번호 / 손상현황 / 가로·폭 / 세로·길이 / 개소 / 물량 / 단위 / 비고`가 된다.
모두 이 문서의 규칙으로 정해지며, 앱 화면과 DWG 물량표가 같은 함수를 쓰게 만든다.

번호(3.1)는 `geometry.world` 좌표로 계산한다. 2단계 생성기는 DWG 모델 공간(`geometry.dwg`)에서
동작하지만, 번호는 그 좌표로 다시 매기면 안 된다 — 페이지→모델 변환(`coords.js`가 다루는 문제)이
회전·반전을 포함하면 `geometry.dwg` 기준 순서가 `geometry.world` 기준과 달라질 수 있다. 생성기는
`computeNumbers`가 `geometry.world`로 계산한 결과(손상 id → 번호)를 그대로 가져다 써야 한다.

## 8. 미해결 항목

앞 설계 9장에서 넘어온 것:

- `파손`의 해치 이름
- `ANCHORLK`의 실제 이름
- `철근노출`, `균열/백태`의 선+원 모양
- 해치 축척값
- 도면 단위 — 정해지면 속성 패널의 참고값 줄을 다시 켠다

이 문서에서 새로 생긴 것:

- 번호의 줄 허용 폭을 손상 높이 중앙값으로 두는 규칙이 실제 도면에서 맞는지. 실기기 확인에서 본다.
