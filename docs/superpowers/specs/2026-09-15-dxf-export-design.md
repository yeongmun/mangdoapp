## 1. 목표와 방식

앱에서 표기한 손상을 **원본 도면에 더해서** 캐드 파일로 내려받는다. 도면 위에는 손상 도형·번호·치수가, 오른쪽 끝 **손상물량표**에는 손상마다 한 줄이 들어간다.

방식(사용자 확인 2026-09-14):

- **오토캐드를 쓰지 않는다.** 서버가 DXF 파일을 직접 읽고 써낸다. 그래서 **업로드는 DXF로** 한다(2026-09-14부터 `.dxf` 업로드 지원).
- **표는 진짜 표 객체를 고치지 않는다.** 표 칸의 자리를 계산해 그 위에 글자를 얹는다. 캐드에서 보면 같지만, 표를 더블클릭하면 칸은 비어 있고 글자는 따로 놓인 객체다. 결과가 부족하면 그때 오토캐드 방식(Design Automation)으로 넘어간다.
- 산출물은 **원본 그대로 + 손상 추가**다. 원본의 다른 부분은 한 바이트도 바꾸지 않는다.

앱 화면은 바뀌지 않는다. 산출은 PC 업로드 페이지에서 내려받는다.

## 2. 전제 — 원본 보관

지금은 업로드한 파일을 APS에만 올린다. 앞으로는 **서버에도 보관**한다: `server/data/drawings/<id>.dxf`. 산출은 이 사본에서 시작한다.

- `.dwg`를 올린 도면은 사본이 있어도 산출할 수 없다(이진 파일). 산출 요청에 `DXF로 올린 도면만 산출할 수 있습니다`를 돌려준다.
- 이 변경 전에 올린 도면은 사본이 없다. `원본 파일이 없습니다. 도면을 다시 올려 주세요`를 돌려준다.

## 3. 산출 API와 화면

`GET /api/drawings/:id/export.dxf` (접근키 필요, 다른 API와 같다)

- 성공: `Content-Type: application/dxf`, 파일명 `<원본이름 확장자 뺀 것>_손상.dxf`, UTF-8.
- 손상이 하나도 없으면 400 `표기한 손상이 없습니다`.
- 원본이 없거나 DWG면 2장의 메시지로 400.

업로드 페이지(`upload.html`)의 도면 목록에 `DXF 내려받기` 링크를 더한다. 링크는 접근키를 붙여 요청한다(기존 API 호출 방식과 같다).

## 4. DXF를 다루는 방법

DXF는 `코드\n값\n` 쌍이 이어지는 글자 파일이다. 전체를 객체로 바꾸지 않고 **필요한 곳만 찾아 끼워 넣는다.**

### 4.1 읽기

- 원본을 줄 단위로 읽어 `(코드, 값)` 쌍의 배열로 만든다. 줄 끝(`\r\n` 또는 `\n`)은 원본 그대로 기억해 쓸 때 되돌린다.
- 찾는 것: `HEADER`의 `$HANDSEED`, `$INSUNITS`; `TABLES`의 `LAYER` 표; `BLOCKS`의 각 블록(이름, 안의 엔티티); `ENTITIES`의 `INSERT`(블록 이름·삽입점·배율·회전)와 `ACAD_TABLE`.
- 표 찾기: `ACAD_TABLE` 엔티티의 코드 2가 가리키는 익명 블록(`*T8` 같은 이름)이 실제 표 모양이다. 그 블록의 `LINE`으로 격자를, `TEXT/MTEXT`로 머리글과 글자 높이를 읽는다. 표가 다른 블록(`망도틀`) 안에 있으면 그 블록의 `INSERT`를 따라 좌표를 절대 좌표로 바꾼다.

### 4.2 쓰기

- 새 엔티티는 `ENTITIES` 구역의 `ENDSEC` 바로 앞에 끼워 넣는다.
- 핸들(코드 5)은 `$HANDSEED`부터 1씩 올려 쓰고, 마지막에 `$HANDSEED`를 갱신한다. 같은 핸들이 두 번 나오면 캐드가 파일을 열지 못한다.
- 소유자(코드 330)는 모델 공간 블록 레코드의 핸들이다(`BLOCK_RECORD` 표에서 `*Model_Space`의 핸들을 읽는다).
- 레이어 `신규손상`이 `LAYER` 표에 없으면 추가한다(색 1, 선종류 `Continuous`, 핸들 새로 할당). 표의 항목 수(코드 70)는 캐드가 무시하므로 손대지 않는다.
- 한글은 UTF-8 그대로 쓴다(2018 형식 DXF는 UTF-8이다. `$DWGCODEPAGE`의 `ANSI_949`는 예전 호환용 값이다).

### 4.3 좌표

- 손상은 `geometry.dwg`(도면 모델 좌표, mm)를 그대로 쓴다. `dwg`가 없는 손상(좌표 변환을 못 구한 도면)은 산출에서 **뺀다** — 도면 어디에도 놓을 수 없다. 뺀 개수를 응답 헤더 `X-Mangdo-Skipped`로 알리고 업로드 페이지에서 보여 준다.
- 블록 안 좌표를 절대 좌표로: `절대 = 삽입점 + 배율 × 회전(블록 좌표)`. 회전(코드 50)이 0이 아니면 회전을 적용한다. 배율은 x·y가 같은 것만 지원하고, 다르면 `표의 배율이 가로·세로가 달라 채울 수 없습니다`로 400.

## 5. 손상 도형 출력

`2026-09-12` 설계 8장의 규칙을 그대로 쓴다. 모든 엔티티는 레이어 `신규손상`, 색 1(빨강).

| 유형 | 출력 |
|---|---|
| 선형 (균열, 균열/백태) | 열린 `LWPOLYLINE` |
| 면형 + 해치 | 닫힌 `LWPOLYLINE` + `HATCH` |
| 철근노출 | 닫힌 `LWPOLYLINE` + 기호(4.1절 치수: 나란한 `LINE` 2개, 양 끝 ✕ = `LINE` 4개) |
| 균열/백태 | 열린 `LWPOLYLINE` + 선을 따라 158mm 간격으로 지름 54.4mm `CIRCLE`, 위·아래 번갈아 |

**해치**: DXF의 `HATCH`는 무늬 이름만으로는 부족하고 **패턴 선 정의를 엔티티 안에 담아야** 한다. 정의값은 사내 망도 `docs/exam.dxf`에서 유형별 축척이 이미 반영된 상태로 읽어 둔다(`ANSI31` 50, `ANSI33` 50, `ANSI37` 60, `CORK` 35, `TRIANG` 25, `ANCHORLK` 50 — `2026-09-12` 설계 2장·부록 A). 이 값을 `server/src/export/hatchPatterns.ts`에 고정값으로 둔다. 파손은 기타와 같은 `ANSI33`이다. 해치는 비연관(코드 71 = 0)이며 경계는 닫힌 폴리라인 네 점이다.

**기호 치수**는 `2026-09-12` 설계 4.1절의 실물 mm 값을 그대로 쓴다. 철근노출은 사각형의 긴 변 방향으로 가운데에 선 2개(간격 57.4)를 긋고 양 끝에 ✕(212×212, 짧은 변이 그보다 좁으면 짧은 변 크기)를 둔다. ✕ 중심은 사각형 끝에서 ✕ 반 크기 안쪽이고, 선은 ✕ 대각선과 만나는 곳까지만 긋는다(2026-09-16 캐드 확인 8번 반영 — `2026-09-12` 4.1절).

## 6. 라벨 출력

> **2026-09-16 대체:** 라벨 배치와 레이어는 `2026-09-16-label-layout-design.md`가 대체한다(원 옆 글자, 들여쓰기, 사진번호 레이어, 겹침 방지와 화살표). 글자 높이 300·원 반지름 255·간격 100·`TEXT` 정렬 코드와 "앱과 같은 파일을 서버가 그대로 불러 쓴다"는 방침은 그대로다.

앱 화면과 같은 배치(`2026-09-13` 설계 5.2·9.5)를 도면 실치수로 그린다.

- 글자 높이 300, 번호 원 반지름 255(= 300 × 0.85), 도형 위쪽 경계에서 100 떨어진 곳부터 위로 쌓는다. 줄 간격은 앱과 같은 비율.
- 번호: `CIRCLE` + 가운데 `TEXT`. 이름: `TEXT`(균열은 없음, 기타는 손상현황). 치수 줄: `dimensionTextOf`. 사진 줄: `photoTextOf`. 문구를 만드는 함수는 앱과 **같은 파일**(`server/public/viewer/quantities.js`)을 서버가 그대로 불러 쓴다 — 화면과 도면이 어긋날 수 없다.
- `TEXT`는 정렬 코드 72=1(가운데), 73=2(중간)로 두고 정렬점(11, 21)에 위치를 넣는다. 글꼴 스타일은 `Standard`.

## 7. 손상물량표 채우기

### 7.1 표의 모양 (템플릿 실측, `*T8` 블록 기준)

블록 좌표(mm, 배율 곱하기 전):

- 열 경계 x: `0 | 1003.1 | 2719.2 | 5891.2 | 7088.3 | 8295.0 | 9299.5 | 10695.4 | 11795.5` → 열 8개
- 행 경계 y: `0`(제목 위) `−840.1`(머리글) `−1507.3`(부머리글) `−2174.4`(**데이터 1행 시작**) 이후 **667.1**씩 → 데이터 행 **35개**, 표 아래 끝 −25525
- 셀 글자 높이 150
- 표 삽입점(망도틀 블록 안): `(879243.6, 71105.5)`, 망도틀은 배율 1.2685로 모델 공간에 삽입

산출 코드는 이 숫자를 **박아 두지 않는다.** 표 블록의 `LINE`에서 열·행 경계를, `TEXT`에서 글자 높이를, `INSERT`에서 삽입점·배율을 그때그때 읽는다. 다른 현장 도면의 표가 크기만 다르면 그대로 동작한다(사용자 질문에 대한 답). 위 숫자는 테스트 픽스처와 검증용이다.

### 7.2 열 매핑

| 열 | 채우는 값 | 근거 |
|---|---|---|
| 1 번호 | 표에 이미 인쇄돼 있다. **채우지 않는다.** 손상은 이 번호 순서로 놓는다 | `computeNumbers` |
| 2 손상위치 | 비워 둔다 | 사용자 확인 |
| 3 손상현황 | `statusTextOf` (구간 포함, 예 `균열(0.3mm미만)`) | 2026-09-13 §3.2 |
| 4 가로/폭 | `measured.width` (`formatQuantity`) | |
| 5 세로/길이 | `measured.length` | |
| 6 개소 | `measured.count` (정수 그대로) | |
| 7 면적/연장 | `quantityOf` → `formatQuantity` | 2026-09-13 §3.3 |
| 8 단위 | `unitOf` (`m` / `㎡`) | |

값이 `null`이면 그 칸은 비워 둔다. 번호 N인 손상은 데이터 N행에 들어간다. 글자는 셀 가운데(x·y 중앙)에 높이 = 셀 글자 높이 × 배율로 놓는다. 사진번호는 표에 없다.

### 7.3 표가 없거나 여러 개일 때

> **2026-09-16 대체:** 표 고르기는 `2026-09-16-frame-numbering-design.md`가 대체한다 — 손상마다 자기 망도틀의 표에 들어간다(가장 가까운 표 하나가 아니다). 틀이 하나도 없는 도면에서만 아래 규칙(가장 가까운 표, `표 없음` 경고)이 그대로 남는다. 격자·데이터 1행을 읽는 방법은 그대로다.

- 표(`ACAD_TABLE`)가 하나도 없으면 손상 도형·라벨만 그리고 응답 헤더 `X-Mangdo-Warning: 표 없음`으로 알린다. 산출은 성공한다.
- 표가 여러 개면(템플릿 원본은 7장짜리라 7개) **손상들의 경계상자 중심에서 가장 가까운 표** 하나를 쓴다. 나머지는 비워 둔다. 사용자는 한 장씩 올린다고 했으므로 보통 하나다.
- 표의 데이터 행 수는 격자에서 센다(부머리글 아래 가로선 개수 − 1). 머리글 줄 수도 세지 않고, **`번호` 글자가 있는 행부터 아래를 데이터 행으로 본다**(번호 `1`이 인쇄된 셀의 y 대역이 1행).

### 7.4 35행을 넘을 때

> **2026-09-16 대체:** 넘침 표의 **자리**는 `2026-09-16-frame-numbering-design.md`가 대체한다 — 오른쪽이 아니라 원본 표 **바로 아래**(원본 표 아래 끝에서 머리글 행 높이만큼 띄우고, 왼쪽 끝은 원본과 같다)에 그린다. 오른쪽은 다음 망도틀 자리다. 열 너비·행 높이·머리글·이어지는 번호는 그대로다.

표를 **오른쪽에 한 장 더** 그린다(사용자 확인).

- 새 표는 원본 표와 같은 열 너비·행 높이·머리글로 `LINE`과 `TEXT`를 직접 그린다(표 객체가 아니다). 위치는 원본 표의 오른쪽 끝에서 원본 **첫 열 너비(번호 열)만큼** 띄운 곳, 위쪽 끝은 같은 높이.
- 번호 열은 36부터 이어서 인쇄한다. 70행을 넘으면 세 번째 표를 또 오른쪽에 둔다.
- 새 표의 글자 높이·선 굵기는 원본 표와 같다(원본 값을 읽어 쓴다).

## 8. 번호와 순서

번호는 앱과 같은 `computeNumbers`(왼쪽 우선)로 `geometry.world`에서 계산한다. `geometry.dwg`로 다시 매기지 않는다(`2026-09-13` §7). 산출은 이 번호로 손상을 정렬해 표 행에 놓고 라벨 원에 적는다.

## 9. 검증과 확인

단위 테스트(vitest, `server/test/`):

- DXF 읽기: 쌍 배열 변환, `$HANDSEED`·레이어·블록·`INSERT`·`ACAD_TABLE` 찾기 — 템플릿에서 잘라 낸 작은 픽스처로
- 격자 계산: `*T8` 실측값 픽스처 → 열 경계 8칸, 데이터 행 35개, 1행 y 대역, 셀 중앙 좌표(절대 좌표, 배율·삽입점 적용)
- 엔티티 문자열: `LWPOLYLINE`·`HATCH`(패턴 선 포함)·`CIRCLE`·`TEXT`가 규격대로 나오는지, 핸들이 겹치지 않고 `$HANDSEED`가 갱신되는지
- 표 채우기: 손상 3개 → 행 1~3에 값, `null` 칸은 비움, 손상위치 비움; 36개 → 두 번째 표가 오른쪽에
- API: 손상 없음 400, DWG 도면 400, 원본 없음 400, 정상 200과 파일명

실기기·캐드 확인(사용자):

- 내려받은 DXF를 지스타캐드에서 연다. 원본 도면이 그대로 있고 손상이 빨간색 `신규손상` 레이어로 올라가 있는지
- 손상 위치가 앱 화면과 같은지(1단계에서 좌표 정밀도는 확인했다)
- 표의 각 칸에 값이 들어가고 번호 순서가 앱과 같은지
- 해치 무늬가 사내 망도와 같은 간격인지
- 36개 넘게 그린 도면에서 두 번째 표가 오른쪽에 생기는지

## 10. 미해결·범위 밖

- 도면 단위는 mm로 확정했다(`2026-09-12` 9장). 다른 단위 도면은 지원하지 않고, `$INSUNITS`가 4(mm)·0(없음)·1(인치, 캐드 기본값 잔재)이 아니면 경고 헤더만 붙인다.
- 진짜 표 칸 채우기(Design Automation)는 이 설계 밖이다. 결과가 부족하면 별도 설계로 간다.
