# 망도틀별 번호 매기기 — 틀 인식, 틀마다 1번부터, 틀마다 자기 물량표

- 날짜: 2026-09-16
- 앞선 설계: `2026-09-13-damage-attributes-design.md` §3.1(번호), `2026-09-15-dxf-export-design.md` 7.3(표 고르기)·7.4(넘침 표)
- 이 문서가 위 세 곳을 **대체**한다. 번호를 매기는 순서 규칙(왼쪽 우선, 같으면 위)과 표의 칸 매핑(7.2)은 그대로다.
- 상태: 설계 승인됨 (구현 계획 작성 전). 사용자 확인 2026-09-16.

## 1. 바꾸는 이유

사내 망도 한 장(`docs/빈도면(테이블버전).dxf`)에는 `망도틀` 블록이 가로로 7개 나란히 삽입돼 있고, 틀마다 자기 물량표가 하나씩 들어 있다. 사내 표기는 **틀마다 번호를 1번부터** 다시 센다 — 첫 틀이 15번에서 끝나도 다음 틀은 16번이 아니라 1번이다.

지금 코드는 도면 전체에서 번호를 한 번에 매기고, 손상 무리의 중심에서 가장 가까운 표 하나에 전부 채운다. 이를 틀 단위로 바꾼다.

사용자 결정(2026-09-16):

- 어느 틀에도 들어가지 않는 손상은 **번호 없이** 두고 경고한다.
- DXF 물량표도 같이 바꾼다 — 틀마다 자기 안의 표에 그 틀 손상만 채운다.
- 틀은 블록 이름이 아니라 **"안에 물량표(`ACAD_TABLE`)가 들어 있는 삽입 블록"** 으로 알아본다. 다른 현장 도면에서도 동작해야 한다.
- 넘침 표는 오른쪽이 아니라 **그 표 바로 아래**에 그린다(오른쪽은 다음 틀 안이다).

## 2. 망도틀 인식 (서버)

`server/src/export/frames.ts`(새 파일). DXF 모델 공간(`ENTITIES`)의 **최상위 `INSERT`** 마다:

- 그 블록 안(중첩 `INSERT` 포함, 깊이 4까지 — `findTableCandidates`와 같은 규칙)에 `ACAD_TABLE`이 하나라도 있으면 망도틀이다.
- 틀의 **영역**은 블록 안 도형의 점들을 삽입 변환(위치·배율·회전)으로 옮긴 뒤 감싼 축 정렬 경계상자다. 점을 뽑는 도형: `LINE`(10/20, 11/21), `LWPOLYLINE`(10/20 반복), `CIRCLE`·`ARC`(중심 ± 반지름), `TEXT`·`MTEXT`(10/20), `ACAD_TABLE`(삽입점과 열 너비 합·행 높이 합으로 만든 네 모서리), 중첩 `INSERT`(재귀). `HATCH`는 뺀다(경계가 복잡하고 늘 다른 도형과 겹친다).
- 틀 안의 표: 그 `INSERT`를 따라 내려가며 처음 만난 `ACAD_TABLE`의 후보(`TableCandidate`, 절대 좌표 변환 포함). 둘 이상이면 처음 것만 쓴다.
- 틀 순서: 경계상자 `minX` 오름차순, 같으면 `maxY` 내림차순(왼쪽→오른쪽, 위→아래). 이 순서가 틀의 인덱스(0부터)다.

```ts
interface FrameBounds { minX: number; minY: number; maxX: number; maxY: number }   // mm
interface Frame { index: number; bounds: FrameBounds; table: TableCandidate }
function findFrames(doc: DxfDocument): Frame[]
```

빈도면이면 7개가 나오고, 인덱스 0이 가장 왼쪽 틀이다.

## 3. 틀 정보를 앱까지 보내기

- `DrawingRecord`에 `frames?: FrameBounds[]`를 더한다(표는 넣지 않는다 — 앱은 영역만 쓴다).
- **DXF 업로드**(`POST /api/drawings`)에서 원본을 저장한 뒤 `findFrames`로 계산해 레코드에 넣는다. 원본 파싱에 실패하면 `frames: []`로 두고 `console.error`에만 남긴다 — 업로드는 계속된다.
- **DWG 업로드**는 원본을 읽지 못하므로 `frames: []`.
- **이미 올라간 도면**(`frames` 필드가 없는 레코드)은 `GET /api/drawings`가 목록을 돌려주기 전에 DXF 원본이 있으면 한 번 계산해 저장한다(`DrawingPatch`에 `frames` 추가). 원본이 없거나 DWG면 `[]`로 저장해 다시 시도하지 않는다.
- 앱 뷰어(`main.js`)는 이미 `/drawings` 목록을 받아 두므로, 자기 도면 레코드의 `frames`(없으면 `[]`)를 그대로 쓴다.

## 4. 손상 → 틀 배정 (화면·서버 공통 순수 함수)

`server/public/viewer/quantities.js`에 둔다(번호와 같은 파일).

```js
frameIndexOf(damage, frames) → number | null
```

- 손상의 `geometry.dwg` 경계상자(`boundsOf`)의 **중심**이 틀 경계상자 안(경계 포함)에 있으면 그 틀. 여러 틀에 들어가면(틀이 겹치는 도면) 인덱스가 작은 틀.
- `geometry.dwg`가 없는 손상, 어느 틀에도 없는 손상 → `null`(틀 밖).
- 화면도 `geometry.dwg`를 갖고 있으므로 서버와 **같은 입력**으로 같은 답이 나온다. world 좌표는 쓰지 않는다(페이지→모델 변환에 회전·반전이 있으면 world 경계상자가 달라진다 — `2026-09-16-label-layout-design.md` 4.5와 같은 이유).

## 5. 번호

```js
computeNumbers(damages, frames = []) → Map<id, number>
```

- `frames`가 비어 있으면 **지금과 같다** — 전체를 한 묶음으로 1부터. DWG 도면, 표 없는 도면, 옛 레코드가 여기 해당한다.
- `frames`가 있으면 틀마다 따로 1부터 매긴다. 틀 안에서의 순서는 지금 규칙 그대로(`geometry.world` 중심 X 오름차순, 같으면 Y 내림차순, 같으면 id). 틀 밖 손상은 Map에 넣지 않는다 → 소비자는 `numbers.get(id) ?? null`로 번호 없음을 받는다(라벨은 이미 번호가 없으면 원을 그리지 않는다).
- 번호는 저장하지 않는다(변함없음). 손상을 옮겨 다른 틀로 들어가면 두 틀의 번호가 다시 매겨진다.

### 화면

- `setDamages`에서 번호를 계산하는 자리에 `frames`를 넘긴다. `createOverlay`가 `setFrames(frames)`를 받아 둔다(도면을 열 때 한 번).
- 틀 밖 손상이 하나라도 있으면 저장 배지 옆에 `망도틀 밖 손상 N개 — 번호 없음`을 보여준다. 0개면 숨긴다.
- 속성 패널 맨 윗줄의 번호 자리에는 `-`를 보여준다.

## 6. DXF 산출

- 번호: `computeNumbers(list, frames)` — `frames`는 원본에서 `findFrames`로 다시 구한다(레코드의 것을 믿지 않는다 — 원본이 곧 진실이다).
- 도형·라벨: 지금과 같다. 틀 밖 손상도 도형은 그리고 라벨은 번호 원 없이 그린다.
- 물량표: 틀마다 자기 표(`Frame.table`)에 그 틀 손상만 1번부터 최댓값까지 채운다(빈 번호는 빈 행 — `fillTable` 호출 규칙 그대로). 손상이 없는 틀의 표는 건드리지 않는다.
- 틀 밖 손상은 어느 표에도 넣지 않고 경고 `망도틀 밖 손상 N개는 번호 없이 그려지고 물량표에서 빠집니다`를 낸다(`EXPORT_WARNINGS.outsideFrames(n)`).
- `geometry.dwg`가 없어 건너뛴 손상(`skipped`)은 틀 밖과 같다(번호 없음). 지금까지는 번호를 차지하고 빈 행을 남겼는데, 그 규칙은 없어진다.
- 틀이 하나도 없는 도면(`findFrames`가 빈 배열): 지금 규칙 그대로 — 전체 한 묶음 번호, 가장 가까운 표 하나(`nearestTable`), 표가 없으면 `noTable` 경고.
- 표 배율 검사(`hasUniformScale`)는 틀마다 한다. 하나라도 어긋나면 지금처럼 `ExportError`.

### 넘침 표 (7.4 대체)

- 표를 **바로 아래**에 한 장 더 그린다. 위쪽 끝은 원본 표 아래쪽 끝에서 원본 **첫 행 높이(머리글 행)만큼** 띄운 곳, 왼쪽 끝은 원본과 같다. 열 너비·행 높이·머리글·`LINE`+`TEXT` 방식은 지금과 같다.
- 번호 열은 36부터 이어서 인쇄한다. 70행을 넘으면 세 번째 표를 또 아래에 둔다.
- 틀 밖으로 나갈 수 있다. 캐드에서 옮기면 된다(사용자 확인).

## 7. 바뀌지 않는 것

- 번호 순서 규칙(왼쪽 우선), 손상현황·치수 문구, 라벨 모양·겹침 방지·화살표(겹침 장애물은 틀과 무관하게 도면 전체 손상)
- 표 칸 매핑(7.2), 손상 도형·해치·기호 출력, 저장 형식(schemaVersion 4)
- DWG 업로드는 화면 표기만 되고 산출은 안 된다

## 8. 검증

단위 테스트(순수 함수):

- `findFrames`: 빈도면 픽스처(`server/test/fixtures/mangdo-template.dxf` — 필요하면 틀 2개짜리로 늘린다)에서 틀 개수·순서(왼쪽부터)·각 틀의 표; 표 없는 블록은 틀이 아님; 최상위 `ACAD_TABLE`만 있는 도면은 틀 0개; 회전·배율이 있는 `INSERT`의 경계상자
- `frameIndexOf`: 안/밖/경계 위/겹치는 틀/`dwg` 없음
- `computeNumbers`: 틀 2개에 손상이 나뉘면 각각 1부터; 틀 밖은 Map에 없음; `frames` 빈 배열이면 옛 결과와 같음; 같은 틀 안 순서는 왼쪽 우선
- 산출: 틀 2개 도면에서 각 표에 자기 손상만; 틀 밖 손상 경고 문구와 개수; 틀 없는 도면은 옛 동작; 넘침 표가 아래에 생기고 왼쪽 끝이 같음
- `GET /drawings`: `frames` 없는 옛 레코드가 한 번 계산돼 저장됨; DWG는 `[]`

실기기·캐드 확인(사용자): 틀 두 개에 걸쳐 손상을 그려 화면 번호가 각각 1번부터인지, 내려받은 DXF에서 각 틀 표에 자기 손상만 들어갔는지, 틀 밖에 그린 손상은 원 없이 그려지고 경고가 뜨는지.

## 9. 미해결

- 틀이 겹치거나 포개진 도면(작은 틀이 큰 틀 안에 있는 경우)은 인덱스가 작은 틀이 이긴다 — 실제 도면을 본 뒤 필요하면 "가장 작은 틀"로 바꾼다.
- 틀 영역은 블록 안 도형의 경계상자라 틀 테두리 밖으로 튀어나온 글자가 있으면 영역이 그만큼 넓어진다. 붙어 있는 틀끼리 영역이 조금 겹칠 수 있고, 그때는 앞 규칙대로 왼쪽 틀이 이긴다.
