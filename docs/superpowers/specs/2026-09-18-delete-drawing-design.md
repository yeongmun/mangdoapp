# 도면 삭제 — 휴지통으로 옮기고 복구한다

- 날짜: 2026-09-18
- 상태: 설계 승인됨(사용자 2026-09-18: "복구할수있게 해줘 그리고 앱에서도 삭제가능하게"). 규모가 작아 계획 문서 없이 바로 구현했다.

## 1. 목표

PC 업로드 페이지와 앱에서 도면을 지울 수 있다. 점검 데이터(손상 기록·사진)는 다시 만들 수 없으므로 **서버는 영구 삭제하지 않고 휴지통으로 옮긴다.** PC 업로드 페이지에서 복구한다.

범위 밖: 휴지통 비우기(영구 삭제) UI, 앱에서의 복구, APS(Autodesk)에 올라간 변환본 삭제(자동 만료에 맡긴다).

## 2. 저장 (`server/src/drawingTrash.ts`)

```
data/trash/<drawingId>/
  record.json     { record, deletedAt }  ← drawings.json에서 뺀 레코드
  <objectKey>     원본 DXF/DWG           ← data/drawings/<objectKey>
  damages.json    손상 기록              ← data/damages/<drawingId>.json
  photos/         사진 폴더(썸네일 포함)  ← data/photos/<drawingId>/
```

- 도면 id가 UUID라 휴지통 폴더 이름으로 그대로 쓴다. 복구하면 폴더가 없어지므로 다시 지워도 부딪히지 않는다.
- 옮기기는 `rename`(같은 디스크)이다. 없는 것(사진 없는 도면 등)은 건너뛴다.
- **순서** — 중간에 서버가 죽어도 데이터를 잃지 않게: 지우기는 `record.json 쓰기 → 목록에서 빼기 → 파일 옮기기`, 복구는 `파일 되돌리기 → 목록에 넣기 → 휴지통 폴더 지우기`. 되돌릴 자리에 이미 파일이 있으면 덮어쓰지 않는다(제자리 파일이 최신이다).

## 3. API (접근키 필요)

| 메서드·경로 | 하는 일 |
|---|---|
| `DELETE /api/drawings/:id` | 휴지통으로 옮긴다. `200 { id, name, uploadedAt, deletedAt }`, 없으면 404 |
| `GET /api/trash` | 휴지통 목록(최근에 지운 것이 위) `[{ id, name, uploadedAt, deletedAt }]` |
| `POST /api/trash/:id/restore` | 되살린다. `200 <도면 레코드>`, 휴지통에 없으면 404 |

지운 도면의 손상·사진 API는 도면이 없으므로 404다. 그 도면을 열어 둔 태블릿은 저장 실패 배지를 보고(기기 백업은 남는다), 대기열의 사진은 404로 빠진다(앨범에는 남는다). 복구하면 다시 열어 이어 쓸 수 있다.

## 4. 화면

- **PC 업로드 페이지**: 도면 줄에 **삭제**(빨간 글자) → `confirm` → 목록 새로 고침. 페이지 아래 **휴지통** 카드(비어 있으면 숨김)에 이름·삭제 시각·**복구**.
- **앱 도면 목록**: 도면을 **길게 눌러**(0.6초) 삭제 확인 창. 짧게 누르면 예전처럼 연다. 변환 실패·대기 중인 도면도 길게 눌러 지울 수 있다. 다른 기기가 이미 지웠으면(404) 성공으로 보고 목록만 새로 고친다. 복구는 PC에서만.
