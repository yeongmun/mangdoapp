# 프로젝트 관리 — 도면을 현장·구조물로 묶는다

- 날짜: 2026-09-21
- 기능명세서 F-6(사용자·프로젝트 관리)의 첫 구현, 4단계. 상태: 설계 승인됨(사용자 2026-09-21: "이대로 진행").
- 앞선 설계: `2026-09-18-photo-upload-design.md`(사진 zip), `2026-09-18-delete-drawing-design.md`(휴지통), `2026-09-15-dxf-export-design.md`(산출).

## 1. 목표

도면이 한 목록에 섞여 있다. **프로젝트**(폴더)를 만들어 도면을 묶고, 프로젝트 단위로 사진·산출 DXF를 한 번에 받는다.

사용자 결정(2026-09-21):
- 묶는 구조는 **1단계(프로젝트 › 도면)와 2단계(현장 › 구조물 › 도면) 둘 다** 쓴다 — "두 가지 경우가 다 있어서".
- 프로젝트 정보는 **이름 + 메모**.
- 만들기·고치기·옮기기는 **PC에서만**. 앱은 보기·선택만.
- 묶음 작업은 **사진 zip 전체**, **DXF 전체 내려받기**.

범위 밖: 프로젝트 통째 휴지통, 앱에서 프로젝트 만들기·옮기기, 사용자별 권한, 조사 이력(연도별 보관), 프로젝트 순서 바꾸기(이름순 고정).

## 2. 데이터

### 2.1 프로젝트 (`server/data/projects.json`, `server/src/projectsStore.ts`)

```ts
interface ProjectRecord {
  id: string;            // 'p_' + 32자리 16진수 (newProjectId)
  name: string;          // 앞뒤 공백을 뗀 1~80자
  memo: string;          // 앞뒤 공백을 뗀 0~500자
  parentId: string | null; // null = 최상위. 값이 있으면 그 프로젝트의 하위(구조물)
  createdAt: string;     // ISO
}
```

규칙(모두 `ProjectsStore`가 지키고, 어기면 `ProjectRuleError(code, message)`를 던진다):

| code | 상황 | 문구 |
|---|---|---|
| `name` | 이름이 비었거나 80자를 넘는다 | `프로젝트 이름은 1~80자로 적어 주세요.` |
| `memo` | 메모가 500자를 넘는다 | `메모는 500자까지 적을 수 있습니다.` |
| `parent` | `parentId`가 없는 프로젝트다 | `상위 프로젝트를 찾을 수 없습니다.` |
| `depth` | 상위가 이미 하위 프로젝트다(3단계가 된다) | `하위 프로젝트 안에는 프로젝트를 만들 수 없습니다.` |
| `duplicate` | 같은 자리(같은 parentId)에 같은 이름이 있다(앞뒤 공백 뗀 뒤 글자 그대로 비교) | `같은 자리에 같은 이름의 프로젝트가 있습니다.` |
| `notEmpty` | 지우려는 프로젝트에 하위 프로젝트나 도면이 있다 | `비어 있는 프로젝트만 삭제할 수 있습니다. 도면 N개, 하위 프로젝트 M개가 있습니다.` |

- 깊이는 **2단계까지**다. 최상위 프로젝트는 도면과 하위 프로젝트를 **둘 다** 가질 수 있다.
- `parentId`는 만든 뒤에 바꿀 수 없다(프로젝트 옮기기는 범위 밖). 고칠 수 있는 것은 `name`·`memo`뿐이다.
- 쓰기는 `DrawingsStore`와 같은 방식으로 한 줄로 세운다(`writeJsonFileAtomic`).

### 2.2 도면 레코드

`DrawingRecord`에 `projectId?: string | null`을 더한다. **없거나 null이면 미분류**다 — 지금 있는 도면은 아무것도 바꾸지 않고 미분류로 보인다. `DrawingPatch`에 `projectId`를 더한다. 손상 기록(schemaVersion 5)·사진 폴더·산출 DXF 형식은 **바뀌지 않는다**.

가리키는 프로젝트가 없어진 `projectId`(있을 수 없지만 파일을 손으로 고친 경우 등)는 읽을 때 미분류로 본다.

### 2.3 휴지통과의 관계

휴지통의 `record.json`은 레코드를 그대로 담으므로 `projectId`도 남는다. 복구할 때 그 프로젝트가 **없어졌으면 `projectId`를 null로 바꿔** 미분류로 되살린다. 프로젝트 삭제는 "비어 있을 때만"이고, 휴지통 안의 도면은 비어 있음 판단에 **넣지 않는다**(그래서 위 경우가 생긴다).

## 3. API (모두 접근키 필요)

| 메서드·경로 | 하는 일 |
|---|---|
| `GET /api/projects` | 트리 순서로 편 목록(아래 3.1) |
| `POST /api/projects` `{ name, memo?, parentId? }` | 만든다. `201 <ProjectView>`. 규칙 위반 400(`parent`는 404) |
| `PATCH /api/projects/:id` `{ name?, memo? }` | 고친다. `200 <ProjectView>`. 없으면 404, 규칙 위반 400 |
| `DELETE /api/projects/:id` | 비어 있으면 지운다 `200 { id }`. 없으면 404, `notEmpty`는 409 |
| `POST /api/drawings` (기존) | 폼 필드 `projectId`(선택)를 받는다. 값이 있는데 그 프로젝트가 없으면 APS에 올리기 **전에** 404 `프로젝트를 찾을 수 없습니다.` |
| `PATCH /api/drawings/:id` `{ projectId }` | 도면을 옮긴다. `projectId`는 프로젝트 id 또는 `null`(미분류). `200 <도면 레코드>`. 도면·프로젝트가 없으면 404, 본문에 `projectId` 키가 없으면 400 |
| `GET /api/drawings` (기존) | 레코드에 `projectId`가 그대로 실린다(없으면 없는 채로) |
| `GET /api/projects/:id/photos.zip` | 그 프로젝트와 하위 프로젝트의 모든 도면 사진(4장) |
| `GET /api/projects/:id/export.zip` | 그 프로젝트와 하위 프로젝트의 모든 도면 산출 DXF(4장) |

프로젝트 id 형식(`p_` + 32hex)이 아니면 없는 것으로 본다(404).

### 3.1 `ProjectView` — 서버가 트리를 계산해 준다

클라이언트 둘(PC 페이지, 앱)이 같은 계산을 따로 갖지 않도록 서버가 계산해서 보낸다(`server/src/projectTree.ts`, 순수 함수).

```ts
interface ProjectView extends ProjectRecord {
  depth: 0 | 1;            // 0 = 최상위, 1 = 하위
  path: string;            // 'OO용역 2026' 또는 'OO용역 2026 › A교'
  drawingCount: number;    // 이 프로젝트에 **바로** 든 도면 수
  totalDrawingCount: number; // 하위 프로젝트까지 합친 도면 수
  childCount: number;      // 하위 프로젝트 수
}
```

`GET /api/projects`의 순서: 최상위를 이름순(`localeCompare(…, 'ko')`)으로, 각 최상위 바로 뒤에 그 하위를 이름순으로. 미분류는 프로젝트가 아니므로 목록에 없다 — 클라이언트가 `projectId`가 없는 도면을 세어 보여준다.

## 4. 묶음 내려받기 (`server/src/projectZip.ts` — 이름 짓기는 순수 함수)

zip 안의 폴더:

```
<프로젝트 이름>_사진.zip                 <프로젝트 이름>_손상.zip
  <도면이름>/1_균열(0.3mm미만)_7523.jpg     <도면이름>_손상.dxf
  <하위 이름>/<도면이름>/…                  <하위 이름>/<도면이름>_손상.dxf
                                           건너뜀.txt   (건너뛴 도면이 있을 때만)
```

- 고른 프로젝트에 바로 든 도면은 zip 최상위에, 하위 프로젝트의 도면은 `<하위 이름>/` 아래에 둔다. 하위 프로젝트를 골랐으면 폴더는 도면 단계뿐이다.
- 폴더·파일 이름은 `photoZip.ts`의 `sanitizeEntryName`으로 고친다. `<도면이름>`은 확장자를 뗀 이름이다. 같은 폴더 안에서 이름이 겹치면 ` (2)`, ` (3)`을 붙인다(사진 zip의 규칙과 같다).
- 사진 zip의 파일 이름은 도면별 사진 zip과 **같은 함수**(`zipEntryNamesFor`)로 짓는다 — 번호 규칙이 갈리지 않는다. 사진이 한 장도 없으면 400 `저장된 사진이 없습니다`. store 방식, 스트림.
- DXF zip: 도면마다 `exportDamagesToDxf`를 돌린다. 다음은 건너뛰고 `건너뜀.txt`에 `<경로>: <사유>` 한 줄씩 적는다 — DWG로 올린 도면(`DXF로 올린 도면만 산출할 수 있습니다`), 원본 없음(`원본 파일이 없습니다`), `ExportError`(그 문구), 그 밖의 오류(`DXF 산출에 실패했습니다`). 도면 좌표를 못 구해 빠진 손상·경고가 있는 도면도 `<경로>: 손상 n개가 빠졌습니다` / 경고 문구를 같은 파일에 적는다. 산출된 DXF가 하나도 없으면 400 `산출할 수 있는 도면이 없습니다`(사유가 하나면 그 사유를 괄호로 붙인다). DXF는 글자라 압축(deflate)한다.
- 산출은 도면을 **하나씩** 돌린다(수 MB DXF를 동기로 파싱한다 — 병렬이면 메모리가 겹친다). 산출물을 모아 두지 않는다: **첫 산출이 성공한 순간** 머리글을 보내고 zip을 열어, 앞 항목이 다 쓰인 뒤에 다음 도면을 산출한다(메모리에 DXF 한 장만). 도면 사이마다 이벤트 루프에 차례를 넘긴다. 끝까지 하나도 성공하지 못했으면 아직 머리글 전이므로 400을 준다(2026-09-21 최종 검토 반영).

## 5. PC 업로드 페이지 (`upload.html`, `upload.js`)

- 접근키 카드 아래에 **프로젝트 카드**: 트리 목록(하위는 들여쓰기, 이름 옆에 `도면 N` — 그 프로젝트에 **바로 든** 수. 하위가 있는 최상위는 `도면 N · 하위 포함 T`), 맨 아래 `미분류 (N)`. 한 줄을 누르면 고른 것이 되고, 도면 표는 **그 프로젝트에 바로 든 도면만** 보인다. 고른 것은 `localStorage`(`mangdo.project`)에 기억한다 — 없어졌으면 미분류로.
- 카드 위 버튼: **새 프로젝트**, 그리고 고른 것이 프로젝트일 때 **하위 만들기**(최상위일 때만), **이름·메모 고치기**, **삭제**, **사진 zip 전체**, **DXF 전체**. 입력은 `prompt`(이름, 이어서 메모), 삭제는 `confirm`. 서버의 규칙 위반 문구를 그대로 메시지 줄에 보인다. 프로젝트 목록만 못 읽은 경우(서버 500 등)에도 도면 표·휴지통·폴링은 그대로 동작하고, 그 화면에서만 전부 미분류로 보인다(기억해 둔 선택은 지우지 않는다).
- 고른 프로젝트의 메모를 카드 아래에 보인다.
- **업로드**는 고른 프로젝트로 들어간다(미분류면 `projectId`를 안 보낸다). 업로드 카드에 `올릴 곳: <path>`를 보인다.
- 도면 줄에 **옮기기** 선택 상자(`미분류` + 모든 프로젝트의 `path`). 바꾸면 바로 `PATCH` → 목록 새로 고침.
- 휴지통 카드는 그대로다(프로젝트와 상관없이 전부 보인다).

## 6. 앱 (`App.tsx`, `src/api.ts`, `src/screens/DrawingListScreen.tsx`)

- 목록 화면이 **지금 위치**(null = 맨 위, 또는 프로젝트 id, 또는 `'unfiled'`)를 갖는다.
  - 맨 위: 최상위 프로젝트들(이름, `도면 N`, 메모 한 줄) + 맨 아래 `미분류`(미분류 도면이 있을 때만).
  - 프로젝트 안: 하위 프로젝트들이 먼저, 이어서 그 프로젝트에 바로 든 도면들.
  - 위에 **뒤로**와 현재 위치(`path`). 안드로이드 뒤로 버튼도 한 단계 위로 간다(맨 위에서는 기본 동작).
- 프로젝트가 **하나도 없으면** 지금처럼 도면 목록만 바로 보인다(미분류 단계를 거치지 않는다).
- 마지막 위치를 기억한다: `Paths.document/last-project.json`(`expo-file-system`). 앱을 다시 켜면 거기서 시작하고, 그 프로젝트가 없어졌으면 맨 위로.
- 도면 열기, 길게 눌러 삭제, `보내지 못한 사진` 배지, 당겨서 새로 고침은 그대로다. 새로 고침은 프로젝트와 도면을 함께 다시 읽는다.
- "무엇을 보여줄지"는 순수 함수 `src/projectList.ts`(`listItemsFor(projects, drawings, location)`)가 정하고 `server/test/projectList.test.ts`가 검사한다(`photoQueue.ts`와 같은 방식 — 이 파일은 아무것도 import하지 않는다).

## 7. 바뀌지 않는 것

손상 기록 형식, 뷰어, 사진 업로드·대기열, 도면별 사진 zip·DXF 내려받기, 휴지통 API. 프로젝트가 하나도 없으면 PC 페이지·앱 모두 지금과 같게 보인다(PC는 프로젝트 카드에 `미분류`만).
