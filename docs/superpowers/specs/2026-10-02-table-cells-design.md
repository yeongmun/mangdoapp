# 모델 공간 손상물량표 — 셀 직접 채우기와 표 복제

- 날짜: 2026-10-02
- 앞선 설계: `2026-09-16-frame-numbering-design.md`(틀 인식·틀별 표), `2026-09-16-sheet-overflow-design.md`(넘침 복사본), `2026-09-15-dxf-export-design.md` 7장(표 채우기)
- 이 문서는 **표가 망도틀 블록 밖(모델 공간)에 놓인 도면**에서 위 세 곳의 틀 인식·표 채우기·넘침 복사 규칙을 바꾼다. 표가 블록 안에 든 옛 구조 도면은 위 설계 그대로다.
- 상태: 설계 승인됨(사용자 2026-10-02 "진행해줘"). 시험 파일 C·D(셀 값 + 글자 블록)와 E(표 복제)가 지스타캐드에서 열리고 셀 편집·이동이 됨을 사용자가 확인했다.

## 1. 바꾸는 이유

사내 새 템플릿(`빈도면(V_Table35).dxf`, 2026-10-01)은 `망도틀` 블록 안에서 손상물량표를 빼고, 모델 공간에 틀마다 `ACAD_TABLE` 하나씩을 얹었다. 표가 블록 밖에 있으면 틀마다 다른 값을 **셀에 직접** 넣을 수 있다 — 블록 안에 있을 때는 삽입 7개가 같은 블록을 보여 셀을 채울 수 없었고, 그래서 선 위에 글자를 얹었다.

지스타캐드 시험(2026-10-02):
- 셀 값만 바꾸거나 그래픽 캐시(310)까지 지워도 **값이 보이지 않는다.** 캐드는 표가 가리키는 `*T` 글자 블록을 그대로 그린다.
- 셀 값 + `*T` 블록에 `MTEXT`를 넣으면 보이고, 더블클릭하면 값이 들어 있고, 표를 옮기거나 행 높이를 바꿔도 따라온다(캐시를 지우든 두든 같다).
- 표를 통째로 복제(새 엔티티·새 `*T` 블록·새 `BLOCK_RECORD`)해도 열리고 편집된다.

사용자 결정: 셀 직접 입력으로 간다. 캐시는 지운다. 넘침 복사본의 표도 **진짜 표로 복제**한다(②).

지금 코드는 "안에 표가 든 블록"만 틀로 보므로 새 템플릿은 **틀 0개**가 되어 페이지 보기·틀별 번호·넘침이 전부 안 된다. 이것부터 고친다.

## 2. 실제 파일 구조 (조사 결과)

- `망도틀` 블록: `LINE` 61·`TEXT` 42·`HATCH` 8·`LWPOLYLINE` 35·`MTEXT` 1. 표 없음. 삽입 7개, 배율 1.2685 균일, 회전 0.
- 모델 공간 최상위 `ACAD_TABLE` 7개(레이어 0), 틀마다 하나. 38행 × 8열, 행 높이 `141` 38개(첫 행 1071.7, 나머지 851.1), 열 너비 `142` 8개, 표 스타일 `342`, 글자 블록 `343`(BLOCK_RECORD 핸들)·`2`(`*T19` 등). 머리글 3행(`손상물량표` / `번호·손상위치·손상현황·손상규모` / `가로/폭·세로/길이·개소·면적/연장·단위`), 데이터 35행에 번호 `1…35`가 미리 들어 있다.
- 셀 묶음(`171`로 시작, 행 우선 순서, 행×열 개수만큼):
  - 문자열 칸(머리글): `301 CELL_VALUE / 93 0 / 90 4 / 1 글자 / 94 0 / 302 글자 / 304 ACVALUE_END`
  - 정수 칸(인쇄된 번호): `301 CELL_VALUE / 93 0 / 90 1 / 91 n / 94 0 / 300 '' / 302 'n' / 304 ACVALUE_END`
  - 빈 칸: `301 CELL_VALUE / 93 3 / 90 0 / 91 0 / 94 0 / 300 '' / 302 '' / 304 ACVALUE_END`
- `*T` 블록: 표 로컬 좌표(삽입점 기준, 아래로 음수) `LINE` 51 + `MTEXT` 45. `MTEXT`는 칸 가운데(`71` 5), 높이 `40` 191.35(데이터 칸)·184.0(제목), 너비 `41` = 열 너비 − 2 × 44.17, `72` 5, `73` 1, `44` 1.0, 레이어 0, `62` 0. 인쇄된 번호 `1…35`도 여기 `MTEXT`다.
- `BLOCK_RECORD *T19`: `340 0 / 102 {BLKREFS / 331 <표 핸들> / 102 } / 70 0 / 280 1 / 281 0`. `BLOCK *T19`: `70 1`, 기준점 0,0, 이름은 `2`와 `3`에.
- 표 엔티티는 `102 {ACAD_XDICTIONARY 360 … 102 }`와 `160 <크기> / 310 …`(그래픽 캐시 110줄)을 가진다.
- 쓰지 않는 블록 `G$CA81BF59D`·`G$CE54812B6`(옛 표가 든 망도틀 복사본)이 남아 있다. 삽입되지 않으므로 무시한다.

## 3. 틀 인식 (`server/src/export/frames.ts`)

최상위 `INSERT`마다 지금처럼 블록 안을 훑어 경계상자와 안의 표를 구한 뒤:

- 안에 표가 있으면 지금과 같다 — `tableKind: 'inBlock'`.
- 안에 표가 **없으면**, 모델 공간 최상위 `ACAD_TABLE` 가운데 **표 영역의 중심**(삽입점 + 열 너비 합/2, 삽입점 − 행 높이 합/2)이 이 INSERT의 경계상자 안(경계 포함)에 있는 것을 찾는다. 있으면 틀이고 `tableKind: 'modelSpace'`, 여럿이면 중심 x가 작은 것. 없으면 틀이 아니다.
- 모델 공간 표의 `TableCandidate.transform`은 `IDENTITY`다(이미 모델 좌표).
- 틀 경계상자는 블록 안 도형만으로 만든다(지금과 같다). 표는 블록 영역 안에 놓이므로 넓힐 필요가 없다.

```ts
interface Frame {
  …지금 필드…
  tableKind: 'inBlock' | 'modelSpace';
  /** modelSpace일 때 그 ACAD_TABLE의 모델 공간 최상위 순번. inBlock이면 null */
  tableEntityIndex: number | null;
}
```

틀 순서·인덱스 규칙은 그대로다. 앱으로 가는 `frames`(경계상자)도 그대로다.

## 4. 표 채우기 — `modelSpace` 틀 (새 파일 `server/src/export/tableCells.ts`)

선 위에 글자를 얹지 않는다. 표 엔티티와 글자 블록을 **제자리에서 고친다**(시험 D).

### 4.1 셀 값

`fillCells(doc, tableRange, blockName, grid, rows)`:
- 열은 `resolvedColumnMap(grid.headers)`로 찾는다(지금 규칙). 행 i의 셀 = 행 인덱스 `grid.firstDataRow + i − 1`, 열 `column` → 셀 순번 `행 × 열수 + 열`.
- 값이 있는 칸만 바꾼다. 그 칸의 `301 CELL_VALUE … 304 ACVALUE_END` 묶음을 **문자열 칸 형식**으로 바꾼다: `301 CELL_VALUE / 93 '        0' / 90 '        4' / 1 값 / 94 '        0' / 302 값 / 304 ACVALUE_END`. 묶음 밖의 셀 속성(`171…178`, `145`·`170`·`140` 같은 덮어쓰기)은 그대로 둔다.
- 번호·손상위치 칸은 건드리지 않는다. 빈 값(`''`)인 칸도 건드리지 않는다.
- 값은 꾸밈 코드 없이 쓴다(표 스타일의 글꼴을 따른다). `rowValuesOf`의 문구 그대로.
- 표 엔티티의 `160`과 `310`은 전부 지운다.

### 4.2 글자 블록

같은 칸마다 `*T` 블록(`ctx.blocks.get(blockName)`)의 `ENDBLK` 앞에 `MTEXT`를 넣는다:
- 위치 = 칸 가운데(표 로컬 좌표, `grid.colBoundaries`·`rowBoundaries`로 계산 — `cellCenter`의 변환 없는 버전).
- `40` = 그 블록의 인쇄된 번호 `MTEXT`의 높이(`grid.textHeight`), `41` = 열 너비 − 2 × 여백, 여백 = (번호 열 너비 − 번호 `MTEXT`의 `41`) / 2(블록에서 읽는다 — 숫자를 박아 두지 않는다; 못 읽으면 0).
- `71` 5, `72` 5, `73` 1, `44` 1.0, 레이어 `0`, `62` 0, 새 핸들, `330` = 그 블록의 BLOCK_RECORD 핸들(`BLOCK` 머리의 `330`).
- `BLOCKS` 구역 안을 고치므로 `ENTITIES`보다 **먼저** 한다(범위 인덱스가 밀리지 않게 — 아래 7장 순서).

### 4.3 `inBlock` 틀과 틀 없는 도면

지금 그대로 `fillTable`(선 위 글자, 옛 넘침). `손상물량표` 레이어는 어느 쪽이든 만든다(레이어 목록을 늘 같게).

## 5. 넘침 복사본 — `modelSpace` 틀 (`sheetCopy.ts` + 새 파일 `tableClone.ts`)

장 p ≥ 1마다:

### 5.1 틀 블록
펼치지 않고 **틀 `INSERT`를 복사**한다(`copyEntityPairs` + x 이동 `dx`). 블록 안에 표가 없으니 번호 1~35가 따라오지 않는다. 틀 영역의 다른 최상위 엔티티는 지금처럼 `copyRegion` — 단, **그 틀의 `ACAD_TABLE`은 뺀다**(5.2에서 따로).

### 5.2 표 복제 — `cloneTable(ctx, tableRange, dx, page, grid)`
시험 E 방식:
- 새 `BLOCK_RECORD`(이름 `*T<n>`, n = 문서의 `*T` 이름 가운데 가장 큰 번호 + 1부터 하나씩): `0 BLOCK_RECORD / 5 새핸들 / 330 <BLOCK_RECORD 표 핸들> / 100 AcDbSymbolTableRecord / 100 AcDbBlockTableRecord / 2 이름 / 340 0 / 102 {BLKREFS / 331 <새 표 핸들> / 102 } / 70 0 / 280 1 / 281 0`. `BLOCK_RECORD` 표의 `ENDTAB` 앞에 넣는다. 표 머리의 `70`(개수)은 +1 한다.
- 새 `BLOCK … ENDBLK`: 원본 `*T` 블록을 통째로 베끼되 `5`는 전부 새 핸들, `330`이 원본 레코드 핸들인 것은 새 레코드 핸들로, `2`·`3`의 이름은 새 이름. `BLOCKS` 구역의 원본 블록 바로 뒤에 넣는다. 안에서 **번호 열 데이터 행 칸의 `MTEXT`**(`isPrintedNumber`)는 `p·N + i`로 글자만 바꾼다.
- 새 `ACAD_TABLE`: 원본 묶음을 베끼되 `5` 새 핸들, `102 {ACAD_XDICTIONARY…}` 묶음과 `160`/`310` 제거, `343` = 새 레코드 핸들, `2` = 새 이름, `10` += dx. 번호 열 데이터 행 셀은 정수 칸 형식으로 `p·N + i`(`91`과 `302` 둘 다). 나머지 셀은 원본 그대로(원본은 아직 채우기 전이어야 한다 — 7장 순서).
- 그런 다음 그 장의 손상 값을 4장 방식으로 채운다(셀 값 + 새 블록의 `MTEXT`).

### 5.3 뒤 틀 밀기
`entityTransform.ts`의 `ROLES`에 `ACAD_TABLE`을 더한다: 점 `(10,20)`, 벡터 `(11,21)`, 길이·각도 없음. 지금 일반 규칙은 `11/21`(방향 벡터 1,0)을 점으로 보고 `dx`를 더해 표를 깨뜨린다. `isCopyable`은 `ACAD_TABLE`에 대해 **false로 둔다**(복제는 `cloneTable`만 한다 — `copyRegion`이 실수로 베끼지 않게).

`entityBoundsOf`도 같은 역할 표를 쓰므로 표의 경계상자는 삽입점 하나가 된다 — `indexRegions`의 소속 판정에는 표 중심이 더 맞다. `resolvedBounds`에 `ACAD_TABLE` 분기를 더해 `frames.ts`의 `boundsPointsOf`(삽입점 + 너비·높이)로 잰다.

### 5.4 `inBlock` 틀
지금 그대로(`flattenFrameBlock`).

## 6. 산출 흐름 (`exportDrawing.ts`)

지금 7장 흐름에서 `modelSpace` 틀만 갈라진다:

1. `findFrames`, 번호, 배정 — 같다. `gridFor`는 `modelSpace` 표에도 그대로 쓴다(`buildGrid`는 `*T` 블록을 읽으므로 변환이 `IDENTITY`여도 같다).
2. 장 수·간격·누적 이동 — 같다. `modelSpace` 틀은 `isFlattenable` 검사 대신 **항상** 복제할 수 있다(INSERT 복사는 회전·배율을 가리지 않는다). 다만 `buildGrid`가 실패한 표(머리글·번호를 못 읽음)는 지금처럼 `unknownTable` 경고와 함께 채우지 않는다.
3. 라벨·손상 도형 — 같다.
4. **표 작업 순서**(범위 인덱스가 밀리지 않게): ① `BLOCK_RECORD` 추가(TABLES) → ② 블록 복제·`MTEXT` 추가(BLOCKS, 뒤쪽 블록부터) → ③ `ENTITIES` 안 제자리 수정(셀 값·캐시 제거, 뒤 틀 밀기) → ④ 새 엔티티 이어 붙이기(`insertEntities` — 손상·라벨·복사본 INSERT·복제 표). ①②는 앞 구역이라 `ENTITIES` 범위를 밀고, ③은 길이가 바뀌므로(캐시 줄 삭제) 뒤쪽 범위부터 처리한다. 구현은 "고칠 것을 모아 두었다가 구역별로 뒤에서 앞으로 적용"하는 작은 편집 큐로 한다(`DocumentEdits`: `replaceRange(start,end,pairs)`·`insertAt(index,pairs)` → `apply(doc)`가 인덱스 내림차순으로 적용).
5. 복제 표의 셀 채우기는 복제한 묶음을 메모리에서 채운 뒤 ④로 넣는다. 원본 표는 ③에서 채운다.

경고: `sheetCopied`·`sheetCopySkipped`는 그대로. `sheetCopyUnsupported`는 `modelSpace` 틀에서는 나지 않는다.

## 7. 바뀌지 않는 것

앱 화면·저장 형식(v5), 틀별 번호 규칙, `frames` 레코드, `inBlock` 도면의 산출 전부, 레이어 목록, 사진번호·라벨.

## 8. 검증

단위(vitest, 픽스처는 `server/test/fixtures/`에 새 템플릿을 **표 2개·틀 2개로 줄인** 파일을 만든다 — 11 MB 원본은 넣지 않는다):
- `findFrames`: 새 구조에서 틀 2개·각 틀의 표·`tableKind: 'modelSpace'`·`tableEntityIndex`; 옛 픽스처는 `inBlock`; 표 중심이 어느 블록에도 안 들면 틀 아님; 블록 안에도 밖에도 표가 있으면 안쪽이 이김.
- `fillCells`: 값 칸만 문자열 형식으로 바뀜(93/90/1/94/302), 빈 값·번호·손상위치 칸은 그대로, `160`/`310` 제거, 셀 속성(`140` 등) 보존; `*T` 블록 `ENDBLK` 앞에 칸 가운데 `MTEXT`(높이·너비·71=5·330=레코드).
- `cloneTable`: 새 레코드가 `ENDTAB` 앞, `70` +1, 새 블록의 핸들 전부 새 것·`330` 새 레코드, 새 표의 `343`·`2`·`10`, 캐시·확장 사전 없음, 번호 열 `36…70`(셀 `91`/`302`와 `MTEXT` 둘 다), `*T` 이름이 기존과 겹치지 않음.
- `ACAD_TABLE` 이동: `10` 옮기고 `11` 그대로; `isCopyable` false; `resolvedBounds`가 표 영역.
- 산출 통합: 틀 2개 픽스처에 손상 3개 → 각 표 셀에 값, 선 위 글자 없음(`손상물량표` 레이어 엔티티 0개); 손상 40개 → 복사본 INSERT + 복제 표(36~40 채움), 틀 2가 pitch만큼 밀리고 그 표의 `11`은 그대로; 결과가 `parseDxf`로 다시 읽히고 핸들 유일.
- `inBlock` 픽스처의 기존 테스트 전부 그대로 통과.

지스타캐드 확인(사용자, `docs/DXF산출-테스트-결과.md`에 행 추가): 새 템플릿을 올려 틀 7개 페이지 보기; 손상 몇 개 산출 → 셀에 값·더블클릭 편집; 한 틀에 36개 넘게 → 복사본 틀·표(36~)·뒤 틀 밀림; `AUDIT` 오류 0; 옛 도면 산출은 전과 같음.

## 9. 미해결

- 긴 값이 칸 너비를 넘으면 `MTEXT`가 줄바꿈된다(너비 지정). 행 높이는 고정이라 아래 칸과 겹칠 수 있다 — 캐드에서 행 높이를 늘리면 셀 값이라 따라온다. 실제로 나오면 글자 축소를 검토한다.
- 찌꺼기 블록 `G$…`은 그대로 둔다. 사용자가 `PURGE`로 지울 수 있다.
- 표 스타일(`342`)은 공유한다. 복제 표가 다른 스타일을 가져야 할 일은 없다.
