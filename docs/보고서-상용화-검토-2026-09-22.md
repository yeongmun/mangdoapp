# 망도 손상조사 태블릿 앱 — 상용화 검토 보고 (초안)

- 작성: 2026-09-22
- 대상: 팀장·부서장 보고용. IT 용어는 최대한 풀어 썼고, 꼭 필요한 용어는 맨 끝 "용어" 항목에 있습니다.
- 상태: 개발자 초안. 팀 상의 뒤 수정 예정.

---

## 0. 한 장 요약

- **무엇**: 현장에서 태블릿으로 망도(캐드 도면)를 열어 손가락·펜으로 손상을 표기하고 사진을 찍으면, 사무실 PC에서 **손상과 물량표가 채워진 캐드 도면(DXF)**과 **사진 묶음**을 바로 내려받는 앱.
- **어디까지 됐나**: 도면 올리기 → 현장 입력 → 사진 → 산출 → 프로젝트 관리까지 **실제 도면·실제 기기로 동작 확인**을 마쳤습니다. 지금 상태로 소규모 현장 시범 적용이 가능합니다.
- **비용**: 별도 서버 임대 없이 사무실 PC 한 대로 운영. 외부 비용은 오토데스크 변환 요금뿐이며 **도면 파일 하나당 약 400원**(월 무료 구간 있음).
- **가장 큰 제약**: 현재는 **인터넷이 되는 곳에서만** 도면을 열 수 있습니다. 손상 입력·사진은 통신이 끊겨도 저장되지만, 도면 자체를 여는 데 인터넷이 필요합니다. 통신 음영 현장(터널·교량 하부) 대응 방식은 팀에서 정해야 합니다(4장 1번).
- **결정 필요**: 오프라인 방식, 사진 촬영 규칙, 도면 파일 단위, 서버 운영 위치, 계정 관리 방식 등 4장의 항목.

## 1. 배경과 목표

- 지금은 현장에서 종이 망도에 손상을 그리고 사무실에서 캐드로 다시 옮겨 그리는 이중 작업입니다. 사진 번호를 손상과 맞추는 일도 수작업입니다.
- 이 앱은 **현장에서 한 번 입력하면 캐드 도면·물량표·사진 정리가 자동으로 나오게** 하는 것이 목표입니다.
- 사내 캐드(지스타캐드)에서 열리는 결과물을 내는 것을 기준으로 만들었습니다.

## 2. 주요 기능 (업무 흐름 순서)

### 2.1 사무실 PC: 도면 올리기
- PC 브라우저의 업로드 페이지에서 망도 **DXF 파일**을 올립니다. 올리면 자동으로 태블릿용으로 변환되며 보통 수십 초~수 분 걸립니다. 목록에 `대기 → 변환 중 → 완료`로 표시됩니다.
- 도면을 **프로젝트**(현장) 단위로 묶을 수 있습니다. 프로젝트 안에 바로 도면을 넣어도 되고, 프로젝트 › 구조물(교량·터널) › 도면처럼 한 단계 더 나눠도 됩니다.
- DWG는 올릴 수 없습니다(캐드에서 DXF로 저장해 올림). 이유는 3.3 참고.

### 2.2 현장 태블릿: 도면 보기
- 앱을 열면 프로젝트 목록 → 구조물 → 도면 순으로 들어갑니다. 마지막에 보던 위치를 기억합니다.
- 도면은 확대·축소·이동이 되고, 망도틀(도면 안의 틀 하나하나)이 그대로 보입니다.
- 아이패드, 갤럭시탭, 폰(세로·가로) 화면 배치를 각각 맞춰 두었습니다.

### 2.3 현장 태블릿: 손상 입력
- 손상 유형을 고르고(균열, 백태, 박리, 철근노출, 누수, 파손, 기타 등 사내 유형 체계) 손가락이나 펜으로 그립니다. 유형에 따라 **선(균열), 면(박리·백태 등), 점·기호(철근노출 등)** 로 정형화되어 입력됩니다. 자유 낙서가 아니라 캐드에 그대로 옮길 수 있는 형태입니다.
- 그리면 바로 속성창이 떠서 **폭·길이·개소·비고·손상현황·사진번호**를 적습니다. 면적·연장 같은 물량은 자동 계산됩니다.
- **같은 손상이 여러 곳**에 있으면 복제 기능으로 도형만 늘리고 개소가 자동으로 셉니다(번호·표 한 줄로 묶임).
- 망도틀마다 **1번부터 번호**가 자동으로 매겨지고, 틀 밖에 그린 손상은 번호 없이 표시되어 알려줍니다.
- 입력 즉시 저장되며, 통신이 끊기면 태블릿에 보관했다가 연결되면 자동으로 올립니다. 화면에 `저장됨 / 저장 대기 / 저장 실패`가 항상 보입니다.
- 선택 삭제, 마지막 취소, 좌표 확인 기능이 있습니다.

### 2.4 현장 태블릿: 사진
- 속성창의 📷 버튼으로 촬영하면 **앨범에도 저장되고 서버에도 자동으로 올라가** 그 손상에 붙습니다. 사진번호(아이폰은 `IMG_` 뒤 숫자, 갤럭시는 촬영 시각 6자리)가 손상에 자동으로 기록됩니다.
- 서버로는 **줄인 사본**(긴 변 1600px, JPEG 75%)만 올라갑니다. 4~5MB 사진이 300~500KB가 되어 서버 용량과 현장 통신량을 아낍니다. 앨범 원본은 그대로 남습니다.
- 속성창에서 그 손상의 사진을 썸네일로 바로 보고, 누르면 크게 봅니다.
- 통신이 안 되면 앨범에 저장되고 `보내지 못한 사진 N장` 표시가 뜹니다. 연결되면 자동 재전송되며, 표시를 눌러 즉시 재시도할 수도 있습니다.

### 2.5 사무실 PC: 결과물 내려받기
- **손상 DXF**: 원본 망도 위에 `신규손상` 레이어(빨강)로 손상 도형·번호·라벨이 얹히고, 각 틀의 **손상물량표 칸이 자동으로 채워집니다**(손상현황·폭·길이·개소·면적/연장·단위). 표 값은 별도 레이어라 캐드에서 끄고 켤 수 있습니다. 사진번호는 노란 `사진번호` 레이어에 따로 들어갑니다.
- 한 틀의 손상이 물량표 행 수를 넘으면 사내 방식대로 **틀을 통째로 오른쪽에 복사**해 표를 이어 갑니다.
- 표 머리글(가로/폭, 개소 등)을 읽어 칸을 찾으므로 열 순서가 다른 옛 양식의 표도 채워집니다.
- **사진 zip**: `손상번호_손상현황_사진번호.jpg` 이름으로 정리되어 내려받습니다. 손상번호는 DXF의 번호와 같습니다.
- 프로젝트 단위로 **모든 도면의 DXF 전체·사진 전체**를 한 번에 받을 수 있습니다(구조물/도면이름 폴더로 정리, 산출 못 한 도면은 `건너뜀.txt`에 사유).

### 2.6 관리
- 도면 삭제는 **휴지통**으로 옮기는 방식이라 실수해도 PC에서 복구할 수 있습니다(손상 기록·사진까지 함께). 앱에서는 길게 눌러 삭제만 되고 복구는 PC에서만 됩니다.
- 프로젝트는 비어 있을 때만 삭제됩니다.
- 접근키 하나로 앱·PC 페이지의 접근을 막습니다.

### 2.7 검증 현황
- 자동 테스트 978개가 매번 통과합니다(도면 읽기, 물량 계산, 표 채우기, 번호 매기기, 사진, 프로젝트 등).
- 실제 사내 도면 3종과 아이폰·갤럭시로 67개 항목을 확인했습니다(`docs/DXF산출-테스트-결과.md`). 미확인 1건: 아이패드에서 사진 썸네일 표시(기기가 없어 못 함).
- 산출 DXF는 지스타캐드에서 열어 확인했습니다.

## 3. 운영 방식·비용·제약

### 3.1 운영 방식
- **서버는 사무실 PC 한 대**에서 돌아갑니다(설치 프로그램 하나, 실행 명령 하나). 이 PC가 켜져 있어야 앱이 동작합니다.
- 태블릿은 인터넷(사내 Wi-Fi·LTE)으로 이 PC에 접속합니다. 외부 접속은 무료 터널 서비스(cloudflare)로 열어 두며, PC를 재시작하면 주소가 바뀝니다.
- 도면·손상 기록·사진은 모두 이 PC의 폴더(`server/data`)에 쌓입니다. **백업은 이 폴더를 복사하면 됩니다.**
- 앱은 현재 Expo Go(개발용 실행기)로 돌립니다. 정식 배포(앱스토어·APK)는 아직 하지 않았습니다.

### 3.2 비용
| 항목 | 비용 | 비고 |
|---|---|---|
| 오토데스크 변환 요금 | **도면 파일 1개당 약 400원** (0.1토큰 × 토큰당 약 $3) | 올릴 때 한 번만. 열기·입력·사진·산출은 무료 |
| 오토데스크 무료 구간 | 매달 일정량 무료 | 정확한 한도는 오토데스크 콘솔에서 확인 필요. 넘으면 자동 청구가 아니라 그 달 변환이 멈춤 |
| 최소 구매 단위 | 33토큰 $99(약 13만 원), 12개월 유효 | 도면 약 330장 분량 |
| 서버 PC·인터넷 | 기존 장비 | 별도 없음 |
| 터널·앱 실행기 | 무료 | |

- 요금은 파일 단위입니다. 한 파일에 망도틀이 몇 개 들어 있든 같습니다. 구조물 하나 = 파일 하나(틀 수십 개)가 비용·성능 모두 적당합니다.
- 예: 월 30개 파일 업로드 시 최대 약 1.2만 원, 무료 구간 적용 시 0원 가능.

### 3.3 현재 제약 (알고 시작해야 할 것)
1. **도면을 열려면 인터넷이 필요합니다.** 도면 그림은 오토데스크 서버에서 실시간으로 받아 옵니다. 손상 입력과 사진은 통신 없이도 되지만, 도면을 새로 열 수는 없습니다. 통신이 되는 곳에서 미리 열어 두고 들어가는 임시 방법은 있으나 앱이 꺼지면 소용없습니다.
2. **DXF만 됩니다.** 서버가 도면 내용을 직접 읽어 산출하는데 DWG는 읽을 수 없어, DWG는 화면에는 떠도 산출·물량표가 안 됩니다. 그래서 업로드를 막았습니다.
3. **한 도면은 한 사람이** 작업하는 것을 전제로 합니다. 두 사람이 같은 도면을 동시에 그리면 나중에 저장한 쪽이 덮어씁니다.
4. **접근키가 하나**입니다. 누가 그렸는지 기록되지 않습니다.
5. **조사 이력이 없습니다.** 도면당 손상 기록이 하나뿐이라, 내년 점검을 하려면 도면을 다시 올려 새로 시작해야 합니다.
6. 사진은 찍기만 됩니다. 앨범에서 고르기, 삭제·교체는 없습니다.
7. 서버 PC가 꺼지면 앱이 멈춥니다. 재시작하면 앱 접속 주소가 바뀌어 앱도 다시 시작해야 합니다.
8. 캐드 전용 글꼴이 아니라 라벨 글자 폭을 어림해 배치하므로, 아주 긴 손상현황 문구는 라벨이 조금 겹칠 수 있습니다.
9. 아이패드 실기기 확인이 아직 없습니다(개발자 보유 기기: 아이폰·갤럭시).

## 4. 팀에서 상의하고 정해야 할 것

번호는 중요도 순입니다. 각 항목에 개발자 의견을 붙였습니다.

### 4.1 통신 음영 현장(오프라인) 대응 방식 — 가장 중요
- 상황: 터널·교량 하부 등 데이터가 안 터지는 현장이 실제로 있음.
- 선택지:
  - **A. 지금대로** — 통신 되는 곳에서 도면을 미리 열어 두고 들어간다. 추가 개발 없음. 앱이 꺼지면 못 엶.
  - **B. 오토데스크 오프라인 방식 시험(1~2일)** — 변환 결과를 태블릿에 미리 내려받아 오프라인에서 열게 함. 되면 개발량이 적고 화면은 지금과 같음. 다만 태블릿 앱 안에서 되는지, 오토데스크 약관에 맞는지, 좌표가 같은지 해 봐야 앎. 도면당 변환 요금이 한 번 더 들 수 있음.
  - **C. 자체 뷰어 개발** — 우리 서버가 DXF를 직접 그려 주는 뷰어를 만든다. 오프라인이 **확실히** 되고 오토데스크 의존·요금이 없어짐. 개발량이 큼(사진 기능·프로젝트 기능 두세 개 분량). 캐드 글꼴·해치 무늬는 캐드 화면과 조금 다르게 보임.
- 개발자 의견: B를 먼저 시험하고 안 되면 C. 오프라인이 반드시 필요하고 오토데스크 의존을 없애고 싶으면 바로 C.

### 4.2 사진 촬영 규칙
- 손상 하나에 사진 몇 장을 찍을지(대표 1장? 근접+전경 2장?).
- **복제 손상**(같은 손상이 5곳)의 사진: 대표 한 곳만 찍을지, 곳마다 찍을지. 지금은 손상 단위로 사진이 붙고 곳마다 구분은 없음.
- 사진 파일명 규칙 `손상번호_손상현황_사진번호.jpg`가 보고서 작성 흐름에 맞는지.
- 사진 화질: 서버 보관본을 긴 변 1600px로 정했음(사내 PC 축소 설정과 동일). 보고서 인쇄 기준에 맞는지.
- 사진을 **보고서(사진대지)에 어떻게 넣을지** — 지금은 zip으로 받아 수작업. 자동 사진대지가 필요하면 5장 참고.

### 4.3 도면 파일 단위
- 파일 하나에 무엇까지 넣을지(구조물 하나? 경간 하나?). 요금은 파일당 400원이라 합칠수록 싸지만, 너무 크면 태블릿이 느려짐. 개발자 의견: **구조물 하나 = 파일 하나(틀 수십 개)**.
- 프로젝트 구조를 어떻게 쓸지: `용역 › 구조물 › 도면` 2단계로 통일할지, 작은 용역은 1단계로 할지. 이름 규칙(예: `2026 OO용역`, `A교`).

### 4.4 서버를 어디에 둘지
- **사무실 PC**(지금): 비용 0, 대신 PC가 켜져 있어야 하고 재시작 시 접속 주소가 바뀜. 담당자가 필요.
- **클라우드 서버**(월 1~3만 원대): 24시간 동작, 주소 고정, 여러 명 동시 사용에 유리. 개발 추가 필요(설치·보안 설정).
- 어느 쪽이든 **데이터 백업 담당과 주기**를 정해야 함.

### 4.5 계정·권한
- 접근키 하나를 공유할지, 사람별 계정을 둘지. 사람별로 하면 "누가 언제 그렸는지"가 남고 삭제 권한을 나눌 수 있음.
- 앱에서 도면 삭제를 허용할지(지금은 길게 눌러 삭제 가능, 복구는 PC에서). 현장 실수 방지를 위해 앱에서는 막는 선택도 가능.

### 4.6 손상 유형·물량 기준 확정 (기능명세서 미해결 항목)
- 손상 유형 목록과 유형별 물량 산정 기준이 사내 표준과 맞는지 최종 확인.
- 레이어 이름(`신규손상`, `손상물량표`, `사진번호`), 색, 라벨 형식(`#001`)이 사내 도면 표준과 맞는지.
- 물량표 양식이 여러 종류라면 표본을 모아 확인(머리글로 칸을 찾으므로 대부분 되지만, 머리글이 없는 표는 기본 순서로 채움).

### 4.7 동시 작업
- 한 도면을 여러 명이 나눠 그릴 일이 있는지. 있으면 손상 단위 합치기 기능이 필요(지금은 도면 단위 덮어쓰기).

### 4.8 조사 이력
- 같은 구조물을 매년 점검할 때 이전 손상을 보면서 그릴지(진전 비교), 매번 새로 시작할지. 이력이 필요하면 5장의 "조사 이력" 개발 필요.

### 4.9 기기
- 아이패드 vs 갤럭시탭 중 무엇으로 통일할지. 펜 사용 여부. 아이패드는 사진 썸네일 확인이 아직 안 됨.
- 앱 배포 방식: 지금은 개발용 실행기(Expo Go)로 QR 스캔해 실행. 정식 배포(앱스토어·사내 배포)를 할지, 언제 할지.

### 4.10 시범 적용
- 어느 현장, 누가, 언제. 시범에서 볼 항목(입력 속도, 종이 대비 시간, 산출물 수정 필요량).
- 시범 중 발견한 요구를 모을 방법(메모·사진).

### 4.11 DWG 차단 확정
- DWG 업로드를 막는 것으로 했음. 현장에서 DXF 변환을 누가 할지(캐드 담당? 업로드하는 사람?).

### 4.12 오토데스크 계정·요금 담당
- 오토데스크 개발자 계정(API 키)을 누가 관리할지. 토큰 구매 시점과 결제 방법. 사용량 확인 주기.

## 7. 용어

| 용어 | 뜻 |
|---|---|
| DXF / DWG | 캐드 도면 파일 형식. DWG는 오토캐드 전용 형식, DXF는 공개 형식이라 프로그램이 직접 읽을 수 있음 |
| 오토데스크 APS | 오토데스크가 제공하는 웹 서비스. 도면을 태블릿 화면용으로 변환해 주고 뷰어 프로그램을 제공. 변환할 때만 요금 |
| 토큰(Flex) | 오토데스크 요금 단위. 1토큰 약 $3. DXF 변환 1회 = 0.1토큰 |
| 서버 | 도면·손상·사진을 보관하고 앱과 PC 페이지에 데이터를 주는 프로그램. 지금은 사무실 PC에서 실행 |
| 터널(cloudflare) | 사무실 PC의 서버를 외부 인터넷에서 접속할 수 있게 열어 주는 무료 서비스 |
| 망도틀 | 망도 안의 틀 하나(도면 블록). 틀마다 손상 번호가 1번부터 시작 |
| 레이어 | 캐드에서 도면 요소를 겹쳐 놓는 층. 켜고 끌 수 있음 |
| 휴지통 | 삭제한 도면을 보관하는 서버 폴더. 복구 가능 |
| Expo Go | 개발 중인 앱을 설치 없이 실행하는 도구. 정식 배포 전 단계 |

## 부록 A. 기술 구성 (IT 담당 참고)

- 앱: React Native(Expo). 도면 뷰어는 오토데스크 뷰어를 앱 안 웹 화면에서 구동.
- 서버: Node.js. 파일 기반 저장(`server/data`). 오토데스크 변환·뷰어 토큰 발급, 손상 JSON 저장, DXF 직접 편집 산출, 사진 보관·썸네일, 프로젝트·휴지통.
- 손상 데이터의 원본은 JSON이고 DXF는 산출물입니다. 도면 좌표계 기준으로 저장하므로 캐드에 그대로 옮겨집니다.
- 코드·설계 문서·검증 기록은 사내 GitHub 저장소에 있습니다. 설계 문서는 `docs/superpowers/specs/`, 실기기 확인 기록은 `docs/DXF산출-테스트-결과.md`.
